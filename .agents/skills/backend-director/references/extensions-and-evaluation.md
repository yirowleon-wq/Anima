# Extension contracts and honest verification

These responsibilities preserve the runtime/evidence semantics as Anima evolves. Port names are design roles, not claims that every same-named interface exists. Read current [status](../../../../docs/CURRENT_STATUS.md), [navigation](../../../../PROJECT_NAVIGATION.md), [broker](../../../../src/main/capabilities/broker.ts) and [roadmap](../../../../docs/DEVELOPMENT_ROADMAP.md) before implementation. A fictional campus and chosen sample material can support meaningful local use when their actual model, visual, state, action and recovery behavior works. Real-campus data, private accounts and API connections are optional extensions with their own source and permission boundaries.

## Eight extension roles

1. **ObservationPort:** source-bearing domain observation, with fresh/stale/partial/unknown/not-connected/forbidden status, actual data, coverage, acquired time and expiry. Sensors, weather, timetable and activity do not bypass owners to write lasting understanding.
2. **CapabilityProvider:** broker-registered read/write capability with scope, expected revision and Action/Approval/Attempt/Receipt.
3. **TaskRecipe:** a visible, editable, disableable way of reusing successful cooperation, preserving its sources and permission boundary.
4. **AudienceProjector:** a minimal projection for self, peer busy/free, group or public audience, without private reasons.
5. **DeliveryPort:** actual preparation/approval/send/receipt across notifications, push and external messages.
6. **SyncPort:** object-level causal versions and privacy fences/tombstones across independent hosts.
7. **ModelProvider:** real transport contracts and future local-only/offline or multimodal processing. The normal live route is Luna through the locally authenticated Codex CLI session; selection, authenticated availability, requested model and actual response identity remain distinct. Engineering work and product requests keep separate purposes and records, and account credentials are not project assets.
8. **StorageProtectionPort:** real platform key management, at-rest encryption and a portable export that excludes withdrawn content. Protecting one credential/payload is not encryption of the whole SQLite/index/backup.

## Verification layers

**Mechanism:** run relevant existing `check`, `test` and `test:hermes` commands. Inspect whether the affected guard would catch the actual risk: exception overwriting a norm, missing fence, stale child adoption, local-only leak, false success, or a stream emitted before secret redaction. Historical mutation lists are risk examples, not permission to create a mutation suite or break a healthy implementation. Do not lower a check to make it pass.

**Authorized model:** use only the current explicitly authorized path and inspect the real response model. A configured transport name is not actual response identity, and it does not justify a new paid provider or redundant runner. Continuous story/scenario corpora retain their actual synthetic/design identity and the complete semantic breadth; a count of scenarios does not mean each was run or all requirements were user-approved. Relevant changes, conditions, late results, memory and program readback need actual model participation when that outcome is claimed.

**Host and interface:** inspect and operate actual Electron rendering—role choice, study/notes/material sources, agenda trials, same-camera map takeover, interactive programs, focus, stop and recovery. Credential redaction, rendering, sound and native effects have their own observations. A screenshot, a clickable entry or startup alone does not establish the task outcome.

**Character and experience:** ask whether this is recognizably the selected person, with particular judgment and a real response to the current exchange. A model carrying a name but speaking as an administrative notice is incomplete. Affection, ambition, play and silence each need room. Do not use a satisfaction score or agent assurance instead of the primary agent's actual integrated review.

## Repair the earliest divergence

1. Follow actual ingress → scope/policy → context → Hermes → tool → completion review → public rhythm → renderer until meaning or state first deviated.
2. Distinguish deterministic error, missing/overwhelming context and expression polluted by a tool's bureaucratic wording.
3. Repair the general owner/contract mechanism, preserving healthy work and necessary error handling.
4. Do not insert the failed sentence, person name or an exam-specific regex branch into system prompts to cheat the example.
5. Use materially different natural expressions and an appropriate condition reversal through normal entry points to resolve actual remaining uncertainty. Historical “five phrasings” is a generalization aim, not authorization for scripted new cases or meaningless repetition.
6. Recheck the original trigger and relevant existing checks after the fix, then record actual observations. A separately commissioned external/native integration needs its own evidence; missing required hardware, Mac, independent-host or full-motion conditions cannot become prefilled passes. An unselected optional account/provider or real-campus dataset does not block the functioning fictional/sample track.

Formal twelve-stage development preserves the eight substantive agents and applicable gates of the commissioned work. Keep the complete optional extension goals and their real outcome requirements. Native independence, local functionality, model participation, visual quality and full motion need their own evidence. Correct an in-scope defect rather than deferring it indefinitely.
