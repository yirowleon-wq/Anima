# OpenUI, living surfaces, maps and continuous interaction

This working paper describes goals for Anima's conversational surfaces. Read the complete [dynamic-interface brief](../DYNAMIC_CONVERSATION_INTERFACES.md), the distinct [map-motion design](../MAP_MOTION_DESIGN.md), retained art/intent, current scene/program contracts and actual implementation. Earlier missing paths may now exist; their experience goals remain useful without being fresh defect reports. The twelve stages remain unfinished.

## The main assistant chooses an appropriate expression

The user says the actual problem. The assistant can choose prose, table, graph, map, time band, editable paper, a small interactive experiment or a combination. It unfolds beside the relevant thought and remains something the user can point to and continue discussing through the same understanding/execution loop.

A short answer remains free to be short. Something explained in one sentence does not need a card. A complex question should not be restricted to prose in the name of simplicity. The value is expression, direct use and continuation, not a component count.

OpenUI is the presentation/construction capability, not an alternative name for a model provider or API transport. Similar wording never authorizes a supplier migration, model switch or gateway.

## Preserve what already exists without exaggerating it

Anima already uses a real OpenUI library/renderer with registered domain scenes, `present_view`, source-bound stable references and real rendering. It also has a finite checked interactive-program language/library, parameters, graphics/motion/audio, original program identity, host CAS persistence and next-turn input readback. It is not a zero-to-library integration or a static picture shell.

Registration alone does not show that an ordinary model conversation autonomously selects every suitable view, or that any new learning tool can be constructed. Read the installed package/source and real author contracts before deciding whether an upstream change is needed. A newer example does not install that API, replace Hermes, authorize a different gateway or require another conversation input.

## Trace the entire autonomous path

Capabilities are discoverable; the main model understands the question and chooses a useful form; it obtains sufficient permitted current facts or states a valid computational assumption; it creates/selects a verifiable structure; the host binds original source/object/revision; a trustworthy useful first frame renders; the user acts directly; meaningful selection/current input returns to the same conversation; the next turn reads and changes that same object; cancellation, history and reopening retain their meaning.

Inspect actual input/output at adjacent seams. A SceneRef returned by a tool still needs actual adoption. Directly invoking a renderer or inserting a prepared scene can establish a limited rendering fact, not autonomous construction. Do not feed the model a standard answer or hand-create an assistant message and call the whole loop complete. This paper does not authorize new test fixtures or scripted runners.

## General construction beyond a fixed teaching example

A precise quadratic declaration binds its computed value, curve and tangent. That precision is worth keeping, but the old isolated primitive could not express phase/time/superposition. The current wider program layer exists; the future redesign should generalize it without claiming every desired structure is already supported.

Compare actual alternatives:

- Typed expressions, plots, parameters and time for precise controlled mathematics/science.
- Composable OpenUI elements for diagrams, formulas, tables, input, time controls and explanation, while business views reference real owners.
- A separately designed isolated executable artifact only where a necessary creative interaction truly cannot be declared. It requires a narrow boundary separate from the application, real data, credentials and action powers; this is not current arbitrary-script permission.
- Mature domain-specific components where they serve a stable business purpose, without a new topic-name branch for every screenshot.

Choose combinations by actual need, maintenance, precision, validation, model construction reliability and performance. Controlled need not mean one hardcoded function. Expressive does not mean system access.

Independently check formula, units, coordinates, parameters, domain, approximation, animation time and initial conditions. A reference picture's labels can be wrong. Changing phase should change formula and curve together; paused time should still allow parameter takeover; “Why does it cancel here?” should read the selected location and actual values. A different function or relationship should not require renaming the same dedicated page. Preserve legitimate unsupported ranges instead of inventing a result.

## Shared state remains light and attributable

Domain owners retain facts; Work/frames retain the current question/proposal; Scene/View/Program identities retain presentation; camera, folding, a trial date or local parameter retain interaction state. These duties can share implementation without one DSL string becoming fact storage, intent and action approval at once.

Pan, zoom, local sequence/input, ordering, playback and pause respond immediately. A meaningful place, class, interval, formula position, original range or plan choice can form an exact current reference near the input, with cancellation and the user's existing draft preserved. New evidence/judgment or business writes return through the host. Selection is not permanent interest, trial is not adoption and animation is not a real-world experience.

The program's sending-time input snapshot differs from newer manipulation while an answer is pending. A late patch cannot silently reset the live value. Sparse incremental edits preserve unmentioned declarations; a reset uses declared defaults and current source validity. Preserve host-persisted state rather than relying only on a local visual value.

## A map is a shared understanding of space

Reuse MapSurface, MapService, route topology, CameraOwnership and both graphical/planar implementations. Conversation, standalone map and public preview must not maintain competing facts. The active dataset and license determine what the map represents; synthetic geometry remains a diagram, not real-campus navigation. Never enable location or grant permission. A manual declared origin can remain useful without a device fix.

The first useful frame should answer the current question. For “Can I make the next class?”, show the assumed/known start, destination, actual source path and relevant time, rather than an obligatory flight from far above a city. A previous classroom is a stated hypothetical origin, not fresh GPS. Keep route geometry separate from camera movement; a camera can lead, shift or retain a landmark only where that helps explain.

Approach a junction, bridge or entrance when it contributes information. Gold can focus the current point without making all surroundings compete. A familiar route, repeated view or urgent question can be more direct; exploration can be slower. Duration follows information and hand feel, not a fixed number of seconds presented as truth.

For A→B→A, place A is stable while its stop instances and directed legs differ. Recompute a return under actual constraints rather than reverse the outward animation. Preserve direction and the active segment when paths overlap. “Look at A” changes viewing; “Go back to A before leaving” may change the itinerary. Read the actual sentence and current reference.

Pan, scroll, touch, keyboard input or “Wait, look here” takes camera/emphasis ownership immediately. An old callback cannot seize it again, and a new request can begin from the actual present view without completing an obsolete animation. Use existing ticket/version/lifecycle and real completion signals, not an independent second controller or several timers guessing completion.

A building choice followed by “here” binds the actual place/selection. Arrival needs a permitted actual observation or a user report, never the route cursor. Entrances, estimated access, conditional paths and unknown interior detail retain their actual source. A beautiful camera does not establish an open gate.

## Inline, focus and return are the same map

Unfold near relevant prose with enough readable road/endpoint space. A complex comparison can focus a larger surface while keeping selection, camera intent, conversational context and the same meaningful input entry. Folding returns to the original conversation position; reopening continues instead of replaying an entrance sequence. Resizing can fit the relationship rather than preserve an arbitrary numeric zoom.

Avoid accidental scroll-to-map-zoom capture. Keep keyboard, touch/two-finger and reduced-motion paths. Streaming prose and a local patch must not repeatedly rebuild WebGL, reset camera/selection or displace scroll/draft. A statement name and React instance identity are not automatically equivalent; follow the actual mounts.

Offscreen historical surfaces should not all render or poll location. Use an honest snapshot/resume strategy and the same facts/selection in the planar fallback, with its actual viewpoint limits. Reopening a historical view is not an implicit fresh source query or renewed permission.

## Each part of daily life needs its own complete relationship

Time and calendar show before/after class, work, travel, preparation, cleanup, rest and usable fragments. Moving a candidate place or trial interval updates dependent space/time facts together. “Leave this open” remains legitimate.

Weather/air use the question's actual daily/hourly window and supported field scope. A selected afternoon continues the planning question. Decorative light is not a current observation; missing values do not become a sunny icon or an unsupported minute-level prediction.

Grades/units can be one direct answer, a term table or a meaningful trend. Preserve original course/term/source, policy, units, denominator and missingness. A selected course's impact calculation rereads that same record. Missing/incomplete grades are not automatically zero; institution/program/year policy is configurable rather than inherited from another system.

Library use compares actual available duration and travel. Reading a reservation is not creating one. An exact seat diagram needs actual geometry, not attractive precision. An existing reservation can connect to route, check-in requirements where supported and the material the person wants to read.

Exercise separates institutional acceptance, personal record and device measurement. Current rules/deadlines need a real applicable provider. Rest is a choice. A route animation proves neither physical activity nor an official submission; no absent policy becomes a fictional requirement.

Notes retain full independent writing and original pages, with references to a place, course, book or reservation. “Next time nearby” can become a scoped opportunity without silently subscribing to everything. A pause or prior exposure should affect later help meaningfully.

A whole afternoon can connect the same journey and time band. Alter one stop and recompute only what depends on it; compare truly different alternatives such as more room or one extra place, without changing the promised workload to manufacture variety.

No-task exploration can discover the campus, look around or sit somewhere, with spatial narrative and company. Do not fabricate quietness, a free seat, opening hours or local weather. A synthetic place remains explicitly fictional.

Discussion/co-work can unfold actual words, comparable alternatives and a useful next step on a natural paper, with free response rather than mandatory buttons or task registration. The user's main attempt stays theirs.

Study retains original question, personal attempt, disclosed help and a stopping point. Indicating a line continues that help. Current wish determines hint or complete solution; a demonstration parameter is not a user fact or proof of mastery.

Co-creation returns to the original chapter/revision; first person stays with its speaker/world. The current foreground story-setting chain exists and must be preserved; a formerly documented freeze is not a reason to delete it. Wiring and full observed quality remain different claims.

Letters/curiosity offer specific readable content and a route to sources, with keep, put aside, another item and ordinary reply. Reading does not silently establish a subscription or long-term preference. Partial exposure and source withdrawal retain their consequences.

Rehearsal preserves what the user wants to express, with possible simulated responses rather than the real other person's attitude. Collecting a private draft is not sending it.

Phone/tablet continuation remains a full future host/platform goal. Preserve original object and event contracts now; design one-handed, keyboard/orientation, original strokes and away-from-desk use for the actual device. A responsive narrow window does not establish native execution, synchronization or background service.

These families provide breadth; one first slice does not close all of them. Full scenario/timeline collections remain independently useful and must not become fixed pages or production routing.

## History, patches and actual effects

Yesterday's weather or a previous grade snapshot retains its historical meaning. Refresh when actually required and allowed before adopting an old plan, then explain a useful change without silently rewriting history. Save scene/program/library revision and necessary local state. Restore, refresh and edit are separate actions.

Buttons use registered host action paths. Replay, double click, stale revision and cancellation retain original attempt/idempotency semantics. A generated button cannot authorize outward sending, a booking or a payment. Correction, revoked source, changed work and closed view retire old callbacks; a late result cannot reset a new state. Public presentation and private data projection remain distinct.

## Use the retained art in the real product

An inventory counts paths and can include duplicates, rejected material and assets not personally viewed. It does not prove a complete design library was inspected or adopted. Open the actual retained admitted images at useful scale and compare current rendering: intended relationship, implemented portion, missing behavior, proportion and motion still worth preserving.

The user's retained good work remains a foundation, including functional ideas beyond the current runtime. Do not replace it with a few new candidates. Retired/structurally unsound references stay excluded. Maintain actual source/rights, geometry, hashes, purpose and current reference. A generated character picture does not establish redistribution rights.

Continue the four complete light themes and optical space rather than impose every older palette candidate. Let art have presence while text/data remain readable. A known occlusion should be fixed from the current picture, not a coordinate assertion alone. New page families/important interactions are image-led; a clear local repair need not recreate the whole art matrix. The matrix and full first-character performance remain unfinished work.

Compare equivalent content/window/theme at actual size: fonts, margins, transparent layers, long prose, math, tables, narrow layout, focus and the timing of waiting/interruptions. Static empty screenshots cannot establish the working surface's quality.
