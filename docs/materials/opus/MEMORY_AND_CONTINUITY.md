# Memory, understanding, shared experience and progressive capability

This working paper connects the memory and collaboration arguments for Anima's development. It specifies meaning and failure relationships, not mandatory class names or new services. Read the full related material and current implementation; the formal stages remain unfinished. Existing source, owner, permission and recovery semantics remain while a simpler design is developed.

## Understand someone who can change

Anima can remember a person, understand why an earlier choice made sense and allow today's actual words to change that understanding. A person can be contradictory, temporarily change their mind, complain without wanting intervention, or feel distressed while explicitly entrusting an action. Listening, explaining, investigating, comparing and doing can coexist; they are not mutually exclusive help modes.

The main model reads actual words and relevant context. The program preserves identity, sources, typed parameters, time and consequences. Entity search, date parsing, indexes and business validation remain useful for locating candidates or checking a contract; a contains test, regex, classifier or expanded prompt table must not permanently characterize the person or decide the whole exchange before understanding.

## Different responsibilities, one person's material

Original messages/materials preserve what was actually said or read and its immutable revision. Conditional understanding is an interpretation with subject, world, condition, exception and applicable time. Current work records what is being considered, which options were rejected and why, and which explicit result remains due. Business facts—course, grade, event, reservation and action receipt—belong to the relevant domain owner.

Free notes are independent writing a person can edit and recover, not automatic profile material. A shared creation can contain a fictional speaker/world rather than the user's life. Character settings are an explicit choice of relationship, separate from inferred personality. Indexes and summaries are derivatives for a consumer to find something faster, not new authoritative facts.

Reuse existing storage/process where sound. These duties do not each demand a new database or service, and their bodies must not be copied into one universal fact object.

## Preserve the original; support the interpretation

The latter half of a long message, negation, quantity, condition, reason, future effective date or exception can decide its meaning. Follow admission, segmentation, file pagination, context budgets and compaction so economy does not silently remove the decisive clause.

A source address includes immutable content revision, parsing/conversion version and location type. Unicode code points, DOM UTF-16 and bytes are different; so are PDF page/box, image crop, table cell and audio time. If RichText or formula selection cannot be mapped exactly, keep the location unknown rather than manufacturing an anchor from a visually similar substring.

Exact quotation and sufficient semantic support are separate questions. The model may use an actual supplied handle, not invent a source identifier. Deleted or revoked references stay inaccessible rather than jumping to a same-named new file. Opening follows the original permission/version chain.

Current input can support this turn without first becoming persistent memory. Where lasting understanding is appropriate, retain a candidate, original support checks, semantic interpretation, conditional change and controlled commit. Do not rewrite a whole Profile every turn or persist before a no-retention restriction takes effect.

## Give memory several routes back to an original

A useful starting point can be small: a trusted clock/zone; complete current words and explicit controls; referenced objects/revisions and the actual open question; latest corrections and accepted responsibilities; a few relevant original work/material entry points; and discoverable currently lawful capabilities.

Those anchors start investigation rather than prewrite the answer. Irrelevant suggestions can be ignored; insufficient context can be expanded. A new topic does not erase an explicit chosen address, and an attachment-only turn does not permit secretly reading history first.

Use complementary routes: literal text/entity search; time, subject and work navigation; browsing without a keyword; relationships from an original to existing work; optional semantic candidates; and a bounded inquiry where needed. Each can return to the original rather than circulate between summaries.

“We discussed it, but search finds nothing” has several possible causes: an unindexed original, candidate not delivered, narrow wording, a different source scope, searching only assertions rather than original words, or genuine absence. Distinguish them. “It was found but not understood” can instead mean that reasons/exceptions were in neighbors, a tool result was truncated, the main model never read it, or a child returned an empty generalization. A hit is not an interpretation.

Record a negative result's query, scope, coverage and source/index revision so new material or correction can reopen the question. The first empty page does not establish that the person never said it. Search is also bounded: when budget is exhausted, state the actual covered extent and continue whatever help can still stand.

The current optional semantic-resource contract is not proof of default injection or quality. Compare lexical/navigation improvements, appropriate semantic candidates and on-demand deep reading on a concrete problem. If a vector path increases pollution or latency, change it or omit it. Long-term understanding is not a reason by itself to migrate everything into a graph store.

## Conditions enter and leave accurately

Follow a complete continuation of “I am tired, but explain this proof.” Give the requested depth now, do not make tiredness permanent, and if a temporary interpretation is saved know its purpose/support/validity. “I have recovered” reopens current and relevant background candidates. An old condition becoming false does not prove the opposite preference. Unrelated accepted calendar events do not disappear with an emotional change.

Likewise retain the meaning of “It was not the distance; I was already absorbed,” “That was my friend's situation,” “I am writing fiction,” “I am comparing, not choosing,” “Starting next month” and “Except during finals.” Subject, world and time must travel with the interpretation. These examples do not justify dedicated phrase branches.

A refusal's reason can expire. An earlier route can become a candidate again without being automatically accepted. High/low grades, a quiet voice or silence do not by themselves diagnose a personality or psychological state. A new challenge should remain possible.

## Remember what happened together

Keep original question/material, the user's own attempt, the help actually given, the revision actually exposed, explicit reports of reading/understanding/adoption, evidence of an actual outcome and the stop/return point in real work/material/message relationships.

Generated, server-sent, client-received, rendered, played, read, understood, accepted and completed have different evidence. Missing receipt means unknown; a rendering receipt does not measure cognition. Use minimal observable events and natural user feedback rather than eye tracking or a questionnaire after each section.

Partial display, cancelled streaming, folded content, old papers and different device layouts can make “the second one” point to different things. Bind the actual object/revision selected or available then. Only a real ambiguity warrants a question between concrete candidates; a newly sorted list cannot silently replace the old address.

Editing/regenerating chat can create a narrative branch. The actual action ledger remains independent: an executed action does not vanish or replay when the text changes. Unaccepted advice is not shared agreement. Late titles, summaries and preparations check current revision before adoption. Compare personal attempts and disclosed help over time without treating hearing an explanation or receiving a grade as complete independent ability.

## Summaries have consumers and purposes

Navigation titles help find; a conversation checkpoint helps resume; a work summary retains decisions and refusal reasons; topic leads aid retrieval; a current evidence bundle supports a present decision; a preference preserves conditions; an assistance record remembers what kind of help was actually offered. Shared implementation is possible without one master summary doing every job.

A derivative needs its consumer, source revisions, coverage, update time, invalidation/rebuild condition and retirement. A directory summary is not its original body. Rebuild from original evidence where possible rather than repeatedly summarize summaries until qualifications vanish.

Background organization should serve an actual need: index lawful unprocessed words, repair affected derivatives or support a continuing task. A daily all-database reflection without a consumer is not automatically valuable because it is called memory. Rare but critical constraints should not be forgotten merely for low click frequency.

Session-only, do-not-save, excluded-source, attachment-only and public-audience controls apply before the relevant read, transmission or persistence. An independently explicit local reminder can be saved without retaining the entire private chat. Persist-everything-now/delete-later cannot override that boundary.

## Correction, forgetting and restoration follow the whole chain

Correcting a fact or reason, disabling an interpretation, forgetting original words, deleting chat and cancelling a real arrangement are different actions. Let ordinary language express them and give an accurate useful account of scope.

For a local forgotten passage, inspect attributable original spans and dependent assertions, summaries, indexes, caches, queued work, preparations and reusable model-history material. Preserve independent unrelated fragments from the same original. Epoch/version barriers prevent late writes and restoration of old backups from reviving forgotten content.

Stopping use, erasing every backup and retracting content already disclosed externally have different feasible effects. State necessary consequences without making each correction a forensic report. Keep transparent recoverable migration; an empty replacement store cannot prove the user's continuity survived.

## Four forms of work, selected when useful

Deterministic code suits time arithmetic, permission/revision checks, aggregation, indexing and actual receipts. A single bounded model task can produce a neutral title or a scoped conversion/candidate. A bounded agent inquiry can react to tools, change route and compare sources. A persistent task can return later to observe or fulfill a responsibility through a real queue/scheduler.

These are choices, not four required new frameworks. A worker has a real consumer, purpose, original/source subset, object revision, budget, latest useful time and stop condition. Return evidence and gaps so the main assistant can ask, reread or reject adoption. A worker does not rewrite long-term character, sign new permission or accept a proposal for the user.

Account for foreground, children, background, compression, review and retry in the total budget. Useful foreground help can arrive while a title/index finishes; an independent answer need not fail because a background derivative failed. Preserve enough completion capacity, while checking that a budget strategy has not removed crucial tools so early that nothing can be accomplished.

## Acquire capability, method, evidence and permission separately

An overview says what exists and its actual availability. A full contract says input, output, effects, errors and inspection. A method helps use it. Evidence comes from an actual read. Permission comes from the valid human/host scope.

A missed initial candidate must not make a capability permanently undiscoverable. Keep directory search, pagination, descriptions and a way to revisit. Adequate current evidence can support a direct answer; a harder question can expand investigation.

Prefer real schemas supported by the runtime. A describe/call gateway, if needed, is limited to registered, described, revision-matched capabilities and validates the actual contract. Arbitrary natural language or shell is not a do-everything permission bridge.

A useful personal method retains its actual origin, conditions and counterexamples and can be amended or disabled. It is not automatically installed privileged code. Bundled and user-authored methods can appear through one understandable discovery path without asking the user to manage a technical skill catalog.

Large scoped data reads can use a validated AST. Truly necessary computation needs an appropriate bounded execution design with network, directories, credentials, resources and output controlled. Preserve input revision, units, denominator, filter and coverage. A program finishing does not establish the analysis used the right population or policy.

## Original files and multimodal evidence stay readable

Handle real types: TXT/Markdown encoding and source bytes; PDF text versus scan pixels, formulas and crops; table formulas/cached values/hidden and filtered ranges; actual image pixels; audio transcript revisions; archive members. An extension does not prove Office/OCR/audio support or full reading. Preserve those concrete future needs without inventing present support.

For a meaningful image question, the correct bytes must enter the actually supported and authorized product model/perception route and affect the judgment. A path, seen flag or developer's own image inspection does not prove the product model saw it.

Public display, notification, search title, ARIA, hover and export are disclosure paths too. Use appropriate projections. Hidden DOM does not make a private disclosure disappear. Keep source/processing/audience responsibility in the host while the interface remains usable.

## Use counterfactuals to understand a benefit

If a model can answer with sufficient lawful evidence but the product cannot, first examine context, source selection and return paths. A relevant changed condition should be able to change the decision; unrelated history should not derail it. A corrected reason can yield the same conclusion, so inspect the premise rather than reward superficial rewording.

Compare a few anchors, full on-demand reading, excessive prefilling, semantic candidates, bounded inquiry and direct main-model reading on an actual difficulty. Keep an enhancement only for its demonstrated benefit and real costs. These are diagnostic choices under the authorized normal workflow and existing checks, not a new test suite. No temporary-emotion write, child, tool or reminder may be the right choice; completing a clear authorized task is equally necessary positive evidence.
