# Anima's product development brief

This overarching working brief describes Anima's development goals, including the first substantial [Sakiko unit](../../stages/01-shared-attention.md). The twelve stages remain unfinished. The [roadmap](../../DEVELOPMENT_ROADMAP.md) holds their full goals and substantive organization.

Please make Anima into the companion that can come close to someone and still do useful work well. Much careful thinking already exists about memory, tools, calendar, maps, initiative, characters and the interface. The painful gap is not merely a missing parameter: a companion described with affection for months can still appear as a program explaining its internal process. It repeatedly certifies that nothing changed, declares a discussion mode, disappears during tools and returns in a generic voice despite the selected character.

I want someone the user can return to after class, after a difficult day or just to exchange a few words. The companion has a recognizable manner, notices the actual sentence, uses a chosen address naturally and investigates when help is needed. Without another message, validly entrusted work may continue and yield a real result, a small discovery or a topic that reconnects. Comfort includes ease, familiarity, affection and not having to remember every obligation alone.

Chosen partner, friend, collaborator and user-authored relationships deserve serious design. Affection, humor, restraint, earnestness and repair after a disagreement have room to differ by character. Capable help is part of that warmth: recover an original, understand a change, connect an arrangement, read actual material, compare a route or take an authorized action. Personality and reliability should occur in the same encounter.

Read README, AGENTS, navigation, contract, architecture, current capability record, continuation and scene/program contracts, then the relevant complete working papers.

Follow a sentence through original-message admission, current controls, context compilation, character guidance, model transport, the pinned Hermes sidecar/AIAgent, tool discovery and execution, returned observations, public text, scene/program construction and renderer input. Follow a selected object back into the next request. For background work, identify what wakes the model without a chat message and which original work consumes the result. Find where reopening actually resumes.

Preserve the existing value: one Hermes loop, bounded independent investigations, exact original evidence and conditional understanding, local arrangements and action receipts, entrustment/opportunity machinery, materials/notes, shared maps, study and creation. Source, actual consumption, observed behavior and remaining design are different states. Distinguish code, the running build, a package and a public preview; an old observation does not describe every current artifact.

## How to work

Formal stages retain eight substantive workers, exclusive write boundaries, one writer per shared contract and primary integration acceptance. The lead personally understands the product and important source arguments; workers also read enough to own real modules and exchange ideas. A team of reports or eight people duplicating one task is not that organization. The product's bounded runtime delegation is separate and remains available.

Use actual authorized resources and relevant existing checks. A particular model channel, private account or mobile device is not a global stop gate, but absent real-model evidence remains absent. Do not insert canned model outputs and claim personality, initiative or autonomous presentation. No new provider/billing, real-person messages, private-data deletion or publication is authorized by this material. Use permitted instance-local/background UI inspection; do not use foreground desktop mouse control or the Computer Use plugin, and never enable location or grant location permission.

Act independently on ordinary authorized reversible work rather than asking the same permission repeatedly. A real recipient, cost or irreversible consequence may need its specific missing decision. Plans, papers and old instructions cannot supply that decision. Healthy sessions continue across local tool errors and waits; actual terminal runtime failure has its own strict evidence/recovery procedure.

The proposed structures, names and order are useful hypotheses. You may find a design itself caused a problem, and replace it with a better one. Preserve user results, data, valid boundaries and capabilities, with an explicit migration and recovery path. Research should improve the actual product rather than end as a framework comparison.

## Put ordinary speech back into the working process

Examine every place that can flatten the voice: stable prompts, character core, interaction defaults, tool meanings/errors, public progress, completion review, summaries, surfaces, notifications, settings and recovery. Inspect what actually enters the model and which guidance overrides which. Do not append “be natural” behind a wall of contradictory instructions and expect it to win.

Separate host-verifiable facts/action responsibility, on-demand methods, character guidance, current agreement and development-only material. Reduce conflict and duplication without deleting the protection. Acknowledgment, confirmed results, meaningful progress and actual completion can be interleaved naturally without four visible labels. The selected character decides when a short reply, a useful partial result or a full explanation fits. Private reasoning is not a waiting animation.

For example, the user asks about a course's grade and units. The companion can acknowledge, obtain the record, say something useful about the result while checking the applicable policy, then show a table that complements the prose. The chosen nickname is optional and person-specific. This is an example of rhythm, not a script to replay or a claim of a query that never happened.

Failure should still be the same person helping. Try a lawful alternate read, narrow a query, return to the original and keep independent results. A missing device position need not stop a manual-origin map. Reaching one reading budget should not hand the entire investigation back to the user as “Ask again.” Tell the concrete remaining gap without a compliance monologue or a false promise to keep checking.

Inspect awkward permanent terms in their actual context. Necessary source, uncertainty and action outcomes can be plain and concise; internal classifications belong in appropriate details. A global forbidden-word list can delete useful facts as easily as it removes jargon. Judge the whole exchange, not a count of renamed labels.

## Make characters into characters

Audit the actual ten built-in identities and editable custom roles: art, written core, relationship/address, saved version, interaction defaults, preview and entry into the real main request. A picture or name is not a complete role. Check first opening rather than relying on “the user can configure it later.” A static example is not a current generated preview and should not be represented as one.

Retain the expressive character writing that works, including sentence rhythm, pauses and specific everyday details. Source availability in a remote copy does not prove absence from an actual shared workspace. Improve precise conflicts and wiring rather than replacing everyone with a uniform careful voice. Preserve custom editing and the user's own choices.

Use official character context, legitimate scenes and first-person performance interviews. Understand why someone addresses a particular person differently, how rhythm changes during serious thought and how outward manner differs from intention. Keep periods/portrayals distinct. Sakiko is not merely a responsible polite advisor; Mutsumi is not an ellipsis generator. Original Anima interaction may interpret a temperament without pretending to quote canon or record the user's actual history.

Character, relationship, address, appearance, real-person information and action permission retain separate owners. Changing an image must not silently change identity or historical authorship. Choosing another character can change expression without rewriting completed actions or existing commitments. A chosen affectionate address never becomes a universal hardcoded nickname.

Consider complete encounters: an ordinary greeting/share, real query, long investigation, failure, correction, affection, serious mathematics, less chatter while busy, return and a prepared discovery. Names/portraits hidden, differences should still be perceptible. That is a judgment from actual use, not a canon-quotation quota or preview score.

## Memory means less repeated self-introduction

Continue through the existing original evidence, understanding, work, notes, materials and domain records rather than inventing another total profile. Own facts, temporary feelings, third people, role settings, hypotheses, story speakers, user writing, campus observations and assistant explanation have different origins.

A past refusal to visit a library might have depended on lacking a computer; carrying it today can reopen the option. Tiredness can coexist with wanting a complete proof. “Not what I meant” can alter the current explanation, proposal and pending work immediately. Do not wait for long-term consolidation before allowing correction.

Find relevant past material without requiring the same keywords. Original browsing, full-text search, time/subject/work navigation, optional semantic candidates and bounded inquiry can cooperate. Candidates are not original reading. If adequate evidence is already present, another search is unnecessary performance. If a note is available but only its preview was read, reread the relevant page instead of asking the user to write it again. Exact quotation and sufficient support for an interpretation need separate judgment.

Keep what we did together: original question, user attempt, help exposed, real stopping point, what was explicitly read/understood/adopted and the actual outcome. Prepared is not read; seen is not independently mastered. An old selection must bind the then-current object/revision rather than an ordinal in a freshly reordered list.

Changes in source, reason, term, residence, interest, permission or time need precise scope. A delayed worker must not restore a withdrawn understanding. A local change must not lock every unrelated domain. Keep independent writing and legitimate history, and preserve the difference between stopping use of an interpretation, deleting original content and cancelling an accepted arrangement.

## Initiative must actually do something

The desired capability includes validly continuing work without a new message: read a permitted source, notice an applicable change, investigate, prepare or act within scope, then return a real result. It is not one extra suggestion at the end of each answer.

Trace the existing work, journals/cursors/acknowledgments, opportunities, same-Harness background inquiry, preparations, message append and notification routes. What refreshes a source? What time/event wakes work? Which tools and current context are available? Where does a result land? What happens when it is opened, refused, paused, superseded or withdrawn? Foreground, minimized/tray, process exit, sleep and reopening have actual different behavior.

An empty preparation shelf or a default prepare-only mode may not produce the experience the user wanted. Provide a low-burden start to an entrustment and an appropriate level of welcome initiative without asking the user to assemble internal switches. Frequency, source permission, fixed commitments and lock-screen preview remain separate. More active does not authorize arbitrary mail or purchases.

Life deserves initiative too: a real sourced discovery, a story continuation, a book the user wanted, an easy walk, a small playable creation or a welcome greeting. Rest, play, relationships, curiosity and no output should not become targets and check-ins. Creative content stays creative; do not fabricate real shared experience.

Keep a pause, one-time notice, later response and cancellation real. Silence is not acceptance; a new title is not a new reason to repeat a notice. Fixed promised reminders remain independent of optional-message cooldown. Close expression never makes the user owe attention or reassurance. Real new conditions can support reconsideration without permanently blacklisting a subject.

An inbox, grades, bookings, outward messages and mobile background each need their actual connection. Complete useful permitted parts and leave a concrete provider/lifecycle entry for unconnected ones. No fake notification or acceptance receipt substitutes for the missing upstream action, and no one reminder demonstration completes the whole proactive stage.

## Make OpenUI an expressive capability the model can use

OpenUI names the presentation/construction layer; model providers and compatible transport protocols are different. A slip between similar names does not authorize moving suppliers.

The current project already has real scenes, finite checked programs, direct inputs, host persistence and next-turn state. Preserve those capabilities while redesigning the full authoring/construction/interaction system. Inspect the installed version and actual API rather than importing every feature from newer online examples or another gateway.

The user should not say “generate a component.” A grade-impact question can call for calculation and a useful graph; a changed stop can alter route and available time; wave superposition can connect formulas, parameters, time and curves. Preserve the same original object through discovery, adequate evidence, checked structure, binding, first useful rendering, direct manipulation, semantic selection, next-turn understanding and saved return.

A fixed parabola or a topic-specific sine branch is not general expression. Compare typed expressions, plots, parameters/time, composable controls/prose and mature domain views. A necessary isolated executable artifact would require a separately designed narrow boundary; arbitrary generated scripts must not inherit Electron, credentials or action powers. The current grammar remains finite and checked until such a route actually exists.

Maps should have a useful first frame, actual source topology, explanation-driven camera movement and immediate user takeover. Preserve repeated stops and directed return legs, selections that return to the same input, inline/focused/folded views and historical recovery. A route cursor reaching its endpoint does not mean a person arrived. Scene updates and streaming text must not remount a map, lose focus or displace the draft.

Review the full breadth in the material library: scheduling and actual free intervals, weather/air, grades/units, library records, exercise, notes, study, discussion, co-creation, quiet exploration, letters and rehearsal. Existing paths should remain useful; uncompleted goals retain concrete future work. A first slice discovers the shared mechanism rather than reducing the whole product to that slice.

## Let the interface grow from its own beauty

Window light, warm gray and paper, restrained gold and chosen characters are part of a coherent room. Current four-theme direction, real readable content and the retained approved design library govern the work. A picture on disk is not a finished interface.

Inspect actual occlusion of text/grades by a character, a long page hidden under input, duplicate cards with the same facts, scroll captured by a map, inability to interrupt and narrow layouts that merely shrink a desktop. Fix them through real content, proportion, focus and direct behavior. Let the character stay present or yield where reading requires it, without turning every backend record into a permanent panel.

Use image-led work for new page families and important interactions, reusing appropriate approved work where it fits. A clear local repair need not trigger a huge production campaign. The complete first-character performance and ten-person matrix remain development goals. Keep good retained art and its design intent; no small set of new candidates can displace that work. Failed anatomy is not a future reference.

## A continuous development loop

Establish the actual state and a recoverable work point. Understand the complete relevant materials. Reproduce a meaningful discontinuity through an ordinary interaction, find the earliest divergence and compare plausible explanations. Research a few materially different routes, implement a useful change, reconnect it to the real conversation and operate the result. Follow correction, failure, interruption and return into the next turn or day. Repair the shared cause rather than hardcoding a failing sentence.

Then migrate consumers, retire duplicated paths and update actual ownership and capability records. Large files may be split by responsibility, but file length is not the purpose. More model calls do not prove diligence. Keep a simple working route for a simple question while leaving space for a complex investigation.

Verification should discriminate between explanations: actual tool visibility/input, returned evidence, its use in a later answer, original business effects, what was visibly presented and what happens after a change. Keep engineering, integrated rendering, actual model choice and native/long-term evidence separate. A missing real-model trajectory stays an explicit condition, with an actual entry and data requirements rather than a fabricated success.

## Leave a coherent project and an experience worth trying

Keep purpose in README/contract, actual ownership and entry points in navigation/architecture, evidence in current status and a small current continuation. Character source/portrayal, good expressive writing, asset purpose and actual adoption need their own accurate versioned records. The working library supplies full reasoning without becoming another competing current-state page.

The desired result is that the user no longer has to keep saying “use a tool,” “speak as this person,” “show it” or “be proactive.” A real query can have a recognizable voice; tools can have natural continuity; memory can retrieve an original and change understanding; a permitted no-message trigger can return useful help; a program can be used and discussed; a failed operation can recover into the same work.

Those outcomes are development results to establish, not claims made by this document. Show a usable complete unit, proportionate actual evidence, what was protected/simplified, migration and recovery and the specific remaining conditions. Do not use a fixed demonstration or a document count as proof of the whole project. Keep room for an afternoon of conversation, curiosity or simple pleasure without an efficiency justification.
