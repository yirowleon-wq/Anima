# Future baseline commission

This preserved commission establishes a real baseline before scattered repairs. It is future material, not executed work. Read the main commission, engineering method, rules and schema guide. Historical screenshots and text are defect leads, not a complete inventory or ready-to-adopt geometric truth.

Read repository navigation, actual code/data/build configuration, checkout/commit, ownership of uncommitted changes, real startup and the loaded data chain. Do not assume any engine, desktop shell or CRS. Classify assets as production input, historical reference, reproducible cache, restricted material or unknown before any authorized cleanup. Do not delete history merely to organize it.

1. **Running baseline:** use an existing ordinary entry and confirm it runs the current directory/build. Record the real command, service/desktop entry and loaded map data version. Inspect current search, selection, route, tilt and zoom behavior for understanding. This is not final acceptance. If startup fails, record the exact error and useful offline work rather than claiming experience.
2. **Production chain:** locate source → parsing/conversion → canonical entities → derived meshes/lines/surfaces → style/labels → navigation. Identify entry points/functions and runtime-generated buffers, building parts, track markings, land surfaces and shadows.
3. **Complete denominator:** enumerate stable IDs, classes, zones, hierarchy, source mapping and generator batches from actual data. Give missing-ID inputs traceable mappings before assigning IDs. Include hidden layers, outside ports, historical retirement and independent missing-feature candidates. Current screen count is not the total.
4. **Sources and coordinates:** for each input record exact product/layer/version/date/use rights, axis order, unit, provider transform, projection, origin and vertical reference. Unknown stays unknown; filenames do not establish a CRS. Do not move all objects yet.
5. **Zones and classes:** use supported roads/water boundaries or a reasonable computable grid. Cover the declared AOI, recording overlap, gaps and boundary buffers. Define surrounding navigation independently and do not exclude difficult areas. Freeze critical-object and class sets.
6. **Error baseline:** run only existing authorized applicable offline operations, then inspect reported hotspots and representative zones. Record ID, location, observation, candidate cause, evidence needed, severity and dependencies; distinguish confirmed fault from hypothesis. A crossing image alone cannot establish illegality. Map each of the seven historical image leads to real `feature_id` or a locatable pending issue, deduplicating repeated leads without dropping supplemental bridge/junction/channel cases.
7. **Audit entry:** prefer an existing ID-bearing export or focused audit layer. Minimal read-only instrumentation needs actual authorization and must not secretly alter production style to hide errors. Retain camera parameters and normal/audit entry points. This commission does not authorize new runners.
8. **Capability and ownership:** inspect real client/team/worktree capability and actual separable files. Propose truthful exclusive contracts under current governance; do not invent independent chats or override today's collaboration rules with historical assumptions.

The output is a reproducible run entry, accountable complete inventory, located data flow, initial sources and alignment unknowns, frozen AOI/class/critical sets, actual issues, available existing checks and ownership recommendations. Reuse authoritative data rather than maintaining a copied second map.

Exit when production chain and denominator are traceable, unknowns are scoped and locatable, partition coverage is computable, critical reference gaps are identified, each issue can be relocated and user changes remain intact. Missing data/enumeration is a blocker, not zero objects. Baseline can progress to source review with open issues; factual geometry repair requires its relevant coordinate gate first.

If original images are unavailable, use the [phenomenon descriptions](../research/ROOT_CAUSES.md) as leads while explicitly saying the images were not read. Actual runtime/data can establish a more complete baseline; do not pretend to have seen missing attachments or abandon independent work waiting for them. After genuine authorization, continue to eligible next work rather than stopping at a written plan.
