# Map phase 11: integration and affected recheck

Future material under the [shared phase rules](README.md); “recheck” means authorized existing operations and direct observation, not new regression engineering.

**Entry:** proposed commits/patches, contracts, changes, handoffs and prior reviews are available.

**Work:** integration checks source/schema/alignment consistency, file ownership, duplicate repair, lost entities, shared boundaries and cross-class relations, then freezes one candidate commit. Every further merge makes dependent results/views stale. Recompute applicable full-set relations/coverage and revisit affected source, neighborhood, visual and interaction scope.

**Outputs:** integration manifest, actual merge/deduplication explanation, count reconciliation, current integrated results and necessary fresh reviews.

**Exit:** all intended work is truly in one version, cross-family space/interaction holds, stale conclusions have fresh evidence and no blocking handoff remains.

**Do not cross:** Git text merge success is not spatial correctness. Do not splice family PASS reports. Integrated visual changes return to phase ten.

Retain actual members and all dependency versions; no result is current solely because its report date changed.
