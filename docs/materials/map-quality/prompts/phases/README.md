# Twelve historical map work phases

These are map-specific dependency gates for future implementation, **distinct from Anima's twelve product stages and not evidence of executed work**. Current product-stage organization, permissions and verification restrictions prevail. The phases do not authorize new tests, fixtures, runners, location collection, source acquisition or independent user-owned chats.

The structure is not a rigid waterfall. Independent evidence gathering, review preparation and read-only style study can overlap once their prerequisites hold. Do not construct competing production geometries before common reference, schema and facts stabilize. Phases 4–8 may repeat by dependency. An early integrated candidate is useful; later changes invalidate affected old checks and human views.

| Phase | Scope |
| --- | --- |
| [1](01_BASELINE.md) | Real baseline, assets and complete inventory. |
| [2](02_SOURCES_CRS.md) | Sources, lawful use and coordinate reference. |
| [3](03_FULL_SCAN.md) | Full applicable failure queue. |
| [4](04_CLASS_REPAIR.md) | Shared-mechanism/class repair. |
| [5](05_ZONE_GAPS.md) | Zone gaps and joint boundaries. |
| [6](06_MASSING.md) | Supported 2.5D/3D massing. |
| [7](07_SEMANTIC_STYLE.md) | Consistent visual semantics. |
| [8](08_LABEL_SCALE.md) | Labels, scales and transitions. |
| [9](09_AUTOMATED_QA.md) | Complete current-candidate audit using authorized capabilities. |
| [10](10_MANUAL_QA.md) | Direct fact, visual and interaction review. |
| [11](11_INTEGRATE_REGRESS.md) | One integrated version and affected recheck. |
| [12](12_FINAL_ACCEPTANCE.md) | Candidate decision, residuals and actual acceptance. |

Incremental geometry review starts with the first factual repair, not phase nine. Phase ten must concern the actual integrated version; an additional phase-eleven merge marks affected observations stale and sends them back for focused review. Historical automated-review proposals describe future quality goals, not permission to write new checking infrastructure now.

Every phase obeys shared source, permission, risk and state rules. After genuine authorization, proceed through satisfied prerequisites and continue independent work around a blocker without claiming the whole map complete. Bind outcomes to current commit, data/rule/alignment/generator/style versions and actual members. Dependency changes invalidate old outcomes. A phase title or an existing file is not execution evidence.
