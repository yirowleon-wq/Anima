# Shared contract for six responsibility families

These are preserved domain responsibilities for future authorized work, not six automatically created chats or a current headcount requirement. Read MAIN, ENGINEERING_METHOD, CHECK_RULES, SCHEMA_GUIDE and the integrator's actual assignment. Current governance determines whether work uses authorized team agents, isolated worktrees, read-only research or serial writing. Missing contract fields do not grant global write permission: useful read-only study may proceed, production writes may not.

A real contract includes `branch_id`, actual session/worktree locator where applicable, `baseline_commit`, `schema_version`, `alignment_version`, `scope_query`, complete membership hash, read paths, precise `write_allowlist`, forbidden paths, upstream dependencies, cross-domain handoffs, issue prefix, deliverables and reviewer. An empty allowlist is not permission to edit the whole repository. One production file has one writer.

Use `MAP-{family ID}-{sequence}` for genuinely new issues; preserve an existing primary ID for the same fault rather than counting it as several closures. Mark suspected duplicates with `duplicate_of` for integrator review. Write independent record increments in owned paths rather than concurrently replacing a common ledger. Each repair references issue, features, source claims, before/after hashes, rule results and affected neighborhood.

Do not alter shared conversion, schema, severity, thresholds, AOI or another owner's objects to make your result pass. Submit `BLOCKING_HANDOFF` with problem, evidence, conflicting entities, proposed resolution and invalidated dependencies. The integrator decides. Do not invent layer/bridge flags, hide entities or delete difficult cases.

On each upstream change compare contract versions, locate the actual difference and mark dependent results stale. Delivery contains actual commit/patch, `changed_feature_ids`, changed paths, count reconciliation, claim decisions, results, neighborhood effect, open handoffs and rights notes. If source media cannot be distributed, retain only lawful locators/authorization rather than bundling it.

Only `READ_ONLY_RESEARCH_READY`, `MERGE_READY` or `BLOCKED` may describe this assignment's handoff. `MERGE_READY` means ready for review within this contract, not acceptance of a zone or whole map. Do not fill global acceptance independently or use screenshot count, self-attestation or old-input results as proof. Each family's required directions refer to actual scoped observations/results, including location, input versions and a witness. A file existing or a program opening does not constitute their execution.

This document authorizes no family implementation, new tests/fixtures/runners, location permission, device activity or geographic acquisition. Historical proposals for source tools and checker tools remain separated from the canonical map; they confer no authority to create or run them.
