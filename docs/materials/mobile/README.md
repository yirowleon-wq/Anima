# Mobile development materials

These mobile-v2 design and research materials, dated September 12, 2026, preserve the reasoning and detailed constraints for continuing Anima's development. The present direction is iOS/Swift and iPad first, followed by Android. The proposed independent mobile product remains future work.

Read the [Implementation plan](IMPLEMENTATION_COMMISSION.md) for the full proposed work, competing architecture slices, computer development workflow, host ports, lifecycle, entrances, permission tracks, human semantics, visual continuity, data transfer, stages and evidence. Read [Research and architecture](RESEARCH_AND_ARCHITECTURE.md) for the underlying observations, competitor lessons, evidence limits, permission distinctions, architecture rationale, and development tradeoffs.

The complete [72 mobile requirements](../../scenarios/MOBILE_REQUIREMENTS.md) and [39 research sources and eight design briefs](../../scenarios/MOBILE_REFERENCES.md) are companion documents. The implementation plan links their full bodies rather than duplicating its source appendices. Reference dates and reading depths are explicit; implementation must recheck applicable current official documentation. Private source paths, archive identities and personal records are not included.

These documents do not authorize new tests, fixtures, runners, provider calls, location access, device permissions, VM work, or publication. Proposed future acceptance work is distinct from actual evidence. No mobile package, phone-only operation, background capability, vendor eligibility, or cross-app completion is claimed here. The product's twelve-stage plan is separate from the mobile commission's G0–G5 sequence.

Location-dependent design uses manual origins, explicit imports and app-internal virtual positions or trajectories. OS location services and permissions stay off on every platform, including emulators and guests. Preserve simulated provenance, quality, expiry, cancellation and recovery without presenting a simulation as real arrival or official activity credit. The documentation does not establish an implemented virtual workout source.
