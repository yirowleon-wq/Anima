# Preserve the product while giving it an independent mobile host

This mobile-v2 implementation plan retains the full proposed work and current Anima priorities. It describes future development, not a completed mobile stage. The ordinary product comes first; personal enhanced experiments and vendor-qualified capabilities remain distinct. Independent iOS/Swift and iPad work is the first platform direction, followed by Android of equivalent quality. Earlier Android/container suggestions below are conditional alternatives, not a command to reverse that order.

Read the accompanying [research and architecture](RESEARCH_AND_ARCHITECTURE.md), [72 complete mobile requirements](../../scenarios/MOBILE_REQUIREMENTS.md), [39 dated primary references and eight design briefs](../../scenarios/MOBILE_REFERENCES.md) and [current roadmap](../../DEVELOPMENT_ROADMAP.md). Those bodies retain the detailed appendices; their presence establishes no completed device result. Current human instructions override a historical plan, including the prohibition on location services and on new test development without explicit authorization. Uploading or publication requires a separate final human decision.

## 0 · Understand the direction before choosing a stack

Use only the actual Anima workspace and relevant project materials. Current collaboration rules, product principles, design skills, navigation, README, visual direction and collaboration-core source explain what should survive. Historical development commands are evidence of a proposal, not fresh permission. Do not search unrelated chats or disks to reconstruct a project the user did not provide.

The eventual person uses the phone without needing a computer. The collaboration host, conversation, memory, common ground, work, action state and primary database must run or persist inside the mobile app. An authorized cloud model may still require networking. A sophisticated computer development environment is compatible with that goal, but a required PC gateway is not.

This is not replacing Electron with a generic platform chat template, declaring a default wholesale native rewrite, or wrapping a remotely hosted page in an installable shell. Preserve the existing product: its interaction, character, reading, map geometry/projection/camera/selection, evidence and action protocols, and genuinely connected capabilities. Replace platform coupling rather than product value. The old desktop choice does not constrain a future phone host; nor does a personal preference for a new toolkit justify losing the design.

Four conditions belong together: phone independence, retained useful capabilities, a real interface that preserves or deliberately improves the experience, and normal development that is not forced through a simulator for every small change. None alone establishes the whole mobile result. Current iOS/Swift/iPad priority is explicit; evaluate compatible reuse within it rather than treating an older Android-first document as authority.

## 1 · Protect the real baseline without inventory theater

Inspect the actual checkout and shared changes first. Record a real commit or content fingerprint, uncommitted work, launch entry and isolated synthetic workspace. Do not overwrite another contributor's edits, delete a database, uninstall an old app or wipe a simulator merely to obtain a clean-looking result.

Read enough of three areas to locate reusable boundaries:

- The renderer's actual App, settings, conversation views, tokens/styles and shared map interaction, with current design instructions and font/resource licenses.
- Harness/provider/runtime, memory, actions, capabilities, Store/Repository and the shared contracts/routing algorithms.
- Configured weather, campus sources, map resources and host bridges. Distinguish portable HTTP/pure algorithms from Node/OS dependencies and from a declared but unavailable module. A protocol being described does not mean a phone has connected it.

From the normal baseline entrance, retain a small set of meaningful synthetic-content views and normal-speed interactions: empty conversation, long reading, action proposal, memory correction, map selection/route, light/dark treatment and settings. Describe experience invariants such as reading/input relationship, whitespace, type hierarchy, map semantics, selected state, progressive disclosure and returning draft/focus. A phone is not a uniformly scaled desktop screenshot, but neither should it become a platform-component showroom.

An older minimal source package did not contain every map/resource byte. The actual workspace may. Inspect only known project locations. Missing geometry, fonts or historical views must be specific gaps while independent work continues. Random campus data, invented routes, an empty grid or a static picture cannot prove the original map was restored.

Use the actual current renderer's demonstrated dimensionality and representation. A request to preserve projection does not establish a preexisting 3D model. Anima's synthetic demonstration and future lawful real-campus map remain different data scopes.

## 2 · Choose a route through one competitive vertical slice

### Alternative A · Reuse web surfaces and portable TypeScript with native host duties

Where compatible with the selected platform direction, investigate retaining React and the existing map/portable TypeScript semantics inside a qualified native surface. A container such as Capacitor was an earlier candidate, not a selected dependency or an override of the Swift/iPad priority. Phone-native storage, credentials, permissions and scheduling remain real responsibilities.

Maximum reuse does not make `node:sqlite`, filesystem, child processes, Electron IPC/secure storage or desktop device APIs run unchanged. Replace them through actual host ports. A polyfill cannot supply a missing OS capability.

### Alternative B · Retain the product surface while moving necessary execution native

If a qualified shared-core route has evidenced lifecycle, transaction, performance or streaming limitations that cannot reasonably be repaired, consider native execution for the necessary core responsibilities while preserving the same product and map semantics. Under iOS, this requires a real Swift-compatible host/runtime decision; under a later Android track, use the actually supported counterpart.

Do not create a JavaScript memory brain and a separate native memory brain. Keep one owner graph, contracts, causal/version semantics and action authority. Explain actual semantic differences between adapters rather than accepting two competing truths.

### Alternative C · Rebuild more of the surface only for a demonstrated reason

Broader native interface work needs a concrete bottleneck and meaningful mobile interaction benefit. First make a real conversation/map comparison preserving the design language. Explain why less disruptive routes cannot meet the goal, which components remain, and which differences are intentional improvements. “Native is more professional” or “a phone does not run Electron” is not a sufficient argument for rewriting every behavior and aesthetic.

Do not build three complete half-finished products. Compare one common slice: retained product surface/map → local conversation and memory read → one local arrangement write → restart/recovery → an expressly authorized real model call → continued operation with computer services closed. Compare preservation cost, independence, startup/interaction, transaction integrity and recovery risk, then record a short architectural decision. If the real project already has a suitable implementation, evaluate it before creating another to satisfy a document.

## 3 · Let each development surface do the right work

Keep four linked but distinct environments:

1. Computer core work uses the same semantic/coordination core, an isolated owner store and existing relevant checks or direct fault/recovery entrances. Computer evidence does not become phone evidence.
2. A visual development surface renders actual shared components/styles/maps with ordinary refresh and relevant narrow states. A development bridge adapts the host rather than replacing real behavior with canned replies or a separate fake phone UI.
3. A supported simulator exercises actual packaging, OS permissions, installation/migration, process reconstruction, notifications, storage and the chosen rendering host. Browser success cannot certify this layer.
4. An authorized physical target establishes real OS/ABI, graphics/input, permission, background and app-interaction behavior. Mirroring is an observation convenience. Final independence uses the phone's own permitted network after USB and all computer backends/forwarding are closed.

A release includes required code, surfaces and lawful local resources. Development may use supported refresh/debugging, but ordinary release cannot depend on a development server, desktop Node/Python/Electron runtime or debugging gateway, and must not automatically open remote-debugging access. Do not condemn every `localhost` string mechanically: determine whether it denotes a hidden PC service or a qualified packaged local origin, then demonstrate the actual disconnection boundary.

Provide appropriate project-native, independently runnable, idempotent production/development commands where the chosen implementation needs them: environment inspection, shared visual development, ordinary core entry, platform build, supported simulator, explicit-device installation, this-app-only logs and permitted mirroring. Reuse existing commands before adding any. A README placeholder is not an implemented command. New tests, replay harnesses, fixtures or runners still require explicit test-development authorization; this preserved list does not grant it.

The computer workbench serves development. It is not a request to add another end-user desktop product or expand unrelated desktop features before mobile work.

## 4 · Discover the actual platform without elevating around a problem

During an authorized device opportunity, find the installed target SDK, build tools, signing route and device interface. For a later Android path these may include Android Studio/SDK, JDK, the project wrapper, adb/emulator and a chosen mirroring tool. A different native platform needs its own real supported SDK/tools. Verify compatibility and lock actual artifacts rather than copying a historical “latest” version or inventing flags.

Use official distribution channels for genuinely needed tools. Where a license, signing identity, administrator operation, USB authorization or restart requires a person, state the minimal concrete condition. Do not change BIOS or reboot automatically to manufacture compatibility.

Device discovery must distinguish absent, unauthorized, offline and connected targets, with every subsequent command bound to an explicit device identity. After permission exists, read only necessary manufacturer/model, OS/API, ABI and rendering-runtime information. Redact device identifiers in shareable records. Do not collect IMEI, a full installed-app inventory, messages, another app's database, cookies, accounts or photo library.

Follow the actual branch: a supported native install target; another native ecosystem requiring its actual package/storage/permission/scheduling implementation; an explicitly approved compatibility-container experiment; or an unresolved platform condition. A plugin for one platform is not an implementation for another. Renaming a package extension does not change its runtime. Missing signing/authorization remains blocked while independent development proceeds; it never proves physical support.

Do not flash, root, downgrade, unlock a bootloader, establish enterprise ownership, disable protection or click an OS authorization secretly. A higher-privilege track is a separate product/research choice, not an installation-script workaround. Keep OS location services and permissions off on every platform, including emulators and guests.

## 5 · Keep one companion while replacing the host

A useful responsibility structure is:

```text
Product surface: conversation, memory/arrangements, map, design variables and local display
Shared semantics: current meaning, common ground, context, memory, Work, Action and capability protocol
Host ports: repository, model transport, secrets, permission, scheduler, location, clock, app interaction and transfer
Development adapter: computer/browser only for development
Mobile host: actual supported private implementation in the installed app
```

These are responsibilities, not a mandate for many services. Semantic core code must not directly require DOM, Electron or OS-specific modules. UI subscribes to real work and cannot manufacture completion, receive secrets or bypass the authoritative writer to change memory. A compatibility facade can temporarily preserve a caller shape only if it binds explicit replaceable host ports rather than concealing PC IPC.

Provider connects a source, Tool exposes a bounded operation, the domain owner retains business truth, and a procedural method is optional guidance. Do not add an all-purpose personal-information database or require the person to install a developer framework merely to use ordinary help.

Possible port responsibilities include RepositoryPort, ModelTransport, SecretStore, SchedulerPort, PermissionPort, LocationPort, AppInteractionPort, TransferPort and ClockPort. A position port uses manual origins, explicit imports or app-internal virtual coordinates and trajectories; it does not activate OS location. Choose names from the real implementation. A declared type is not a connected port; every promised capability must be reachable from its ordinary conversation/share/assistant entrance, not only through a developer function.

### 5.1 · Storage migration changes transactions, not just library names

The mobile private relational store is the primary owner. Select a suitable native SQLite/equivalent adapter only after actual architecture, transaction, migration, search, failure and applicable encryption behavior are established. Browser preference storage, memory summaries and an optional remote service do not replace that owner.

Review the transition from synchronous database calls to an asynchronous bridge. No network or model call holds a database transaction open. User input, necessary state and its outbox obligation commit atomically. Batch useful queries instead of paying a bridge crossing per row. One writer enforces expectedRevision, stable event identity, idempotency and deletion epoch in actual operations, not merely in interfaces. Typed transaction commands are possible; arbitrary SQL, paths or shell are not exposed to the model.

Original evidence, revisable understanding, common ground/work, live domain state, derived views and indexes remain distinct. Attachments retain source/revision. Do not copy the same fact into competing stores. English retrieval needs actual short names, aliases, negation, unextracted text, long-message conditions and time windows, with an original-text fallback instead of an unsuitable old language/tokenization assumption.

### 5.2 · A native bridge is a boundary

Only qualified trusted packaged content receives the product bridge. An external page or untrusted HTML cannot share an injectable context with native privileges. Markdown and tool returns do not execute scripts. Preserve origin checks, content policy, strict schemas, call identity, scope/epoch, sequence, timeout and cancellation across the bridge. Release debugging is off; a third-party script or downloaded plugin acquires no native authority by being loaded.

Credentials enter through a private native settings path and an actual OS secure-storage implementation, not React, model context or logs. A platform's key-protection mechanism and encrypted credential bytes have different roles; verify the selected Keychain/Keystore-equivalent route instead of claiming a database library supplies encryption automatically.

A native transport may return stream fragments carrying callId, sequence and cancellation, if that route is actually supported. Other designs must establish equivalent secret and outgoing-permission boundaries. Validate the selected provider's documented reasoning/tool/image protocol and actual returned model capability; compatible API syntax is not vision. Preserve Unicode/framing, fragmented tool arguments, multiple calls, malformed results, authentication/rate/server errors, disconnect, cancellation and retry semantics. Protocol state is not personal memory, and hidden reasoning is not public progress. Changed source scope requires a new lawful request chain.

## 6 · The surface can disappear without losing entrusted state

A portable foreground core may use a genuinely supported runtime, but business state cannot live only in a page. The native host keeps checkpoints and pending work; a rebuilt view subscribes instead of dispatching effects again. Rotation, navigation, rendering-surface reclamation, process reclamation, dismissal, forced stop and system restart are different events, not one vague “app closed” condition.

For native reminders, widgets and action inspection, prefer the appropriate actual OS scheduling/host capability. Deferred background work is not an exact alarm; missing exact-time privilege needs a truthful downgrade. Do not depend on page timers, hidden permanent wake locks, a misdeclared foreground task or a demand to disable every battery protection.

If shared-core background execution is needed, first establish the actual supported headless environment and its network, storage and cancellation ports through a narrow slice. The dated container research did not establish a complete DOM/Node runtime, persistent event context or every foreground plugin in background execution. Installing a package does not connect those ports. A finite visible task must use the actual OS rules and explicit user start. Otherwise save the checkpoint and state what will resume when, without claiming background completion.

Foreground/background share run identity, lease/fence, revision and receipts. They cannot host separate planners or duplicate consolidation. Backgrounding, reopening, reimporting or a model repeating a tool must not dispatch the same action twice.

An eligible optional assistant-entry service may have its own lightweight lifecycle. It is not unlimited reasoning, all personal data or permanent automation. Separate entrance service from heavy work and report the actual platform/device behavior, not a cross-brand guarantee.

## 7 · Several entrances return to one matter, without surveillance

An ordinary mobile product should retain these useful entrances as actually supported:

- Main conversation with the product's design, history, stop/retry, draft, sources, memory controls and arrangements.
- Explicitly shared text or a chosen file, retaining original source, temporary content access and work relationship, without reading the whole phone.
- A shortcut and a small widget for a current need such as a quick question or next arrangement, derived from the same work rather than another reminder/calendar store.
- An eligible optional system-assistant role, manually chosen by the person. Where unavailable, a shortcut remains useful; do not claim an unimplemented power-button or wake-word takeover.
- Return after navigation, sharing or another app, with current conversation, stable option numbering, draft and pending inspection intact.

Notification reading, overlays and screen perception are independent optional capabilities, not first-launch compulsory permissions. Core chat, notes, permitted sources and maps must still work without them. Explain the particular unavailable ability rather than repeatedly punishing refusal with a dialog.

First make a request continuable across entrances. A permanent bubble, repeated screenshot capture or reading notifications on every sentence is not evidence of understanding. Position-related entrances retain manual, imported or virtual provenance, quality, expiry, unknown, cancellation and recovery states. Virtual movement is not real arrival or official activity credit; no currently usable virtual workout source is claimed by this plan.

## 8 · Separate three forms of app collaboration

### Ordinary distributable product

Prefer a sufficient permitted formal API/local operation, then eligible partner semantics, then supported link/share/prefilled handoff, and finally the person's control at a real missing step. Opening an app, navigation or shared content does not inherently require global elevated access.

Concrete ordinary work includes resolving a chosen installed target, passing an explicit destination/navigation intention, a supported calendar/matter operation, and receiving shared material into the same work. Query only needed targets or apps chosen by the person. Platform visibility filtering means an unseen target is not necessarily absent.

When direct calendar writing is available and permitted, use the actual event identity and a harmless isolated calendar for a future authorized observation. When only a prefilled form is available, say waiting for save. Anima's own local arrangement may independently be saved. Handoff, opened app, prepared form, dispatched action, verified result and unknown outcome retain different receipts; absent a final result, retain unknown rather than invent success.

### Separately authorized personal enhanced experiment

A future approved experiment must do more than declare an empty interface. Use a physically distinct artifact/application identity; elevated services do not hide in the ordinary release, and experimental permission does not establish distribution approval.

One controlled cross-app task can use an owned companion app or another explicitly permitted harmless target. Read the allowed interface, change a synthetic item and verify the original target result. The phone's own collaboration host chooses and schedules the operation; a computer debug tool may install, initialize or inspect but must not secretly perform the product action.

Do not assume an ordinary app receives a vendor assistant's private virtual environment, invisible multi-instance execution or arbitrary virtual display. Actual support and privilege need evidence. Without them, use visible stoppable collaboration instead of silently occupying the device.

After manual OS authorization, bind the session to target, task, time, action budget and allowed categories. Show start/stop/takeover and expire it. Refusal or withdrawal stops new dispatch. Every screen string remains untrusted data, without authority to change the task, model or limits.

An observation retains foreground app/window, time and relevant content version/summary. Recheck target and permission before action; if changed, observe again rather than clicking stale coordinates. Rechecking is not an atomic observation/action lock and cannot eliminate all rebinding risk. Real sends, payment, secrets, authentication and security changes should use a sufficient qualified API or personal handling, not experimental side effects on real objects.

A text-only model without a qualified visual/semantic observation path cannot claim to see the screen. Perception has a separate adapter but no second personal memory or entrustment store. A chosen debug broker is optional and must already be explicitly enabled; retain actual identity, withdrawal, restart/reactivation cost and device limits. Debug-level is neither root nor vendor signing. Do not elevate automatically to keep the demo running.

Distribution policy is separate from technical availability. The dated research and November 1, 2026 official policy review distinguish autonomous Accessibility use, deterministic human-defined automation and qualified accessibility-tool conditions. Recheck the intended channel at release. Do not disguise an experiment as ordinary distribution, misstate its purpose or claim a universal technical ban. ### Vendor-qualified or system semantic ecosystem

Investigate the selected platform's real semantic capabilities and caller eligibility. Exposing Anima's actions to a system assistant is different from qualifying Anima to invoke another app. A framework registration or permission declaration does not make both directions available.

The earlier Android research described AppFunctions preview, version conditions and runtime allowlisting; actual current SDK/caller admission still needs evidence. Vendor-restricted abilities can require signing/profile/ACL or another actual qualification rather than an ordinary user toggle. Keep a real adapter/refusal state and exact activation condition. Missing admission must not stall the ordinary product or become a claim of system-assistant privilege.

## 9 · Preserve human collaboration instead of a button robot

The current request takes precedence over a work agreement, which takes precedence over applicable soft long-term preferences. Permission, retention and audience remain independent. One input may contain multiple requests and subjects: listening does not erase an explicit note request, and one action does not justify planning the person's whole life.

Common ground retains the current matter, stable displayed options, accepted/rejected scope and reasons, open questions, original addresses and interruption point. Conversation and episode are not interchangeable. A short reference to the second option must reach its actual object/version.

Current words, correction, withdrawal and cancellation affect the present turn first. Background extraction, independent verification, condition integration and indexing follow. Extraction retains necessary preceding question/reference. A processed watermark is a contiguous completed range, not the largest number observed. Unasserted originals remain retrievable.

Today's exception is not permanent character, a hypothesis is not reality, asking for a roommate does not change the user's profile, a suggestion is not a promise and silence is not approval. Dynamic course/weather/position sources retain separate age and coverage. Read what the current decision needs without opening the entire private library or demanding every unrelated field.

Emotional support changes participation. Listen when wanted, analyze seriously when requested, complete a concrete entrusted task, and change the next step after correction rather than apologizing and repeating. Affectionate names and stock comfort are not measures of understanding.

An outward draft receives a minimal permitted brief that preserves intended recipient, time, purpose and tone. Redaction must not delete already supplied requirements and then ask again, while private reasons remain private. Clarify only a material unresolved interpretation, not information already given or lawfully obtainable.

Completion claims need receipts. Timeout does not prove an action failed. If a receiver may have succeeded without returning a result, inspect before retry. Approval binds object, parameters, consequence, version and expiry and is checked again at dispatch. Canceling a goal affects its actual dependent reminders/preparation. An earlier preference is no new execution authority.

## 11 · Local data, backups and transfer have distinct boundaries

Primary store, attachments and rebuildable indexes live in mobile-private storage; the model supplier is not their fact owner. Permitted provider/weather requests can send necessary content to that service. Do not claim that a local app never uses a network.

Credential protection, body encryption and OS backup are different mechanisms. A relational library is not automatic encryption. If using a mature encryption implementation, establish migration, keys and architecture support; otherwise state the real prototype boundary. Define backup/device-transfer exclusions. Temporary content must not survive in logs, worker input, index, protocol cache or export while the UI promises no retention.

Forgetting, disabling and correcting propagate their own meanings through originals, assertions, summaries, indexes, caches, pending consolidation, dependent work and old model chains. Old asynchronous results cannot cross a new epoch. Local deletion cannot recall an external request/effect or teach an unconnected old device about a later withdrawal.

Source refresh, screen mirroring and user-data synchronization are separate. Simulator and phone each own a private primary store. An initial explicit versioned transfer for alternating use can precede a separately scoped multi-master service; do not add a cloud account or automatic merge merely to move a development workspace.

A transfer preserves lineage, schema, stable object/revision, evidence relations, continuous watermarks, deletion/cancellation fences and attachment hashes. It copies no API secret, OS grant, cookies, temporary content or automatically replayable outward action. Use qualified authenticated encryption and the OS file-selection boundary for a chosen transfer. Import stages size/path/hash/reference/password/version validation before atomic application. Do not copy a live SQLite main file while ignoring its WAL.

Repeated import is idempotent. Independent target edits produce a real merge decision/conflict rather than silent overwrite. New local deletion precedes an older package. Imported reminders/outward pending actions are inactive until target-host permission is reverified, preventing two devices from performing one mandate twice.

## 12 · Keep the implementation sequence useful and observable

The earlier G0–G5 sequence is a mobile-topic plan, not a replacement for Anima's twelve stages and not current execution authority. Preserve its dependencies within the present iOS/iPad-first roadmap:

- **G0:** protect the baseline/design, discover actual platform/resources and establish an isolated workspace plus same-product development entrance.
- **G1:** package a narrow real host slice with the retained surface/map and local conversation/work state. Observe independence/reconstruction and actual appearance immediately. Compare another compatible core route only for a real bottleneck, then record the decision.
- **G2:** carry the same collaboration semantics, immediate/background memory, selected model protocol, original tools and ordinary entry into that host. Compare equivalent actual owner state with the original host and retain real supplied capabilities instead of substituting new mock behavior.
- **G3:** connect native storage, secrets, supported notifications/calendar, sharing/shortcuts, mobile map interaction, recovery and explicit transfer. Position ports use manual, explicitly imported or app-internal virtual inputs without OS location services or permissions. Demonstrate PC-off operation and separate any other native-platform/container result.
- **G4:** only as separately authorized, establish a distinct enhanced experiment with a controlled second app, withdrawal, target change, untrusted content and unknown outcomes. Optional assistant/semantic ecosystems have their own actual admission result.
- **G5:** inspect a release-equivalent artifact in simulator and actual device for retained experience, authorized real model behavior, multiple turns, performance, disconnection, recovery and actual effects. Deliver a usable artifact and focused evidence, not a framework count or empty-interface percentage.

Missing credentials, signing, device permission, ecosystem admission or map data should not stop independent work. Preserve partial completion and a precise dependency. Neither a mock “pass” nor a blanket instruction for the person to configure everything resolves the gap.
