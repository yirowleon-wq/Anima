# Engineering, images and tool boundaries

Development tools and Anima's own model requests have separate purposes, permissions and records. Anima's current live model route is Luna through a locally installed, authenticated Codex CLI session. Selecting it does not prove authentication; use the connection check and inspect the actual response identity. Keep credentials, account homes, browser profiles and private data outside the project.

## Image generation

A previously recorded serial Codex PNG workflow produced two 1536 × 1024 images with original/copy hash checks and preservation of the first. That evidence is limited to new image generation under the recorded environment. It does not prove reference-image, editing, mask, concurrent-output, final licensing or UI integration capabilities. Check a suitable supported route before depending on those other capabilities; a routine sample image is not needed merely to repeat the existing observation.

The previously used dedicated new-PNG wrapper is not a general code-writing runner. Its options are not native image API or Codex CLI image flags. Its timestamp/newest-PNG fallback and version suffixes do not prove safe concurrent ownership; keep production serial until request/job identity, exact original path and overwrite protection are bound. Consult the actual installed instructions and complete required notices for any workflow selected; do not invent flags or change to a paid billing route without authorization.

For a real asset request, record request identity, tool/version, project asset identity, original output, dimensions, bytes, hash and intended use. Preserve originals. Use relative paths and provenance in the project manifest; keep private scratch and operational metadata with their owners. Do not invent a prompt that was never recorded. Inspect the actual image before admission. Generation alone is not implemented UI, anatomy approval, motion or a license for character/reference material.

Use the reviewed passports and four-step art pipeline: shared grid/space/contact anchors, a complete first-character sequence, additional characters, then missing slots. Severe structural errors require a clean empty setting and a newly constructed full pose before same-canvas separation. Keep formulas, text, dates and controls live in the product.

## Development organization

For authorized delegated engineering, specify the actual workspace, exclusive write area, expected usable outcome, relevant contracts and evidence limits. Use the selected model and effort and preserve inheritance within delegated sessions. Role names and interface labels do not prove runtime identity; inspect actual turn context when an explicit identity requirement applies.

Formal Anima stages require eight substantive workers and primary integrated acceptance. Give each shared type, bridge, schema, manifest and style owner one writer. Workers contribute real implementation and relevant observations. The lead reads the important original inputs, integrates and uses the result, repairs defects and rechecks before accepting the stage.

A tool failure, unknown skill, input limit, wait, truncated output or normal context compaction is local or ordinary behavior, not terminal model-session failure. Continue the healthy session and correct the operation or use another authorized route. Recovery requires direct evidence of an actual terminal model/runtime error and its termination of the expected response, with the session, error, effect, source and time recorded. An authorized replacement must preserve the original request, model and effort and must not duplicate a pending replacement.

## Product validation

Use Anima's normal entry and existing commands. Connections offers the Luna route and offline demo mode. The retained `dev:luna:test` / `start:luna:test` launch aliases explicitly select the same live route; they do not transfer authentication or credentials. Do not add a provider or paid API use merely to obtain a passing result. Read the returned model identity where available; a configuration label is not response evidence.

Do not create new tests, assertion cases, fixtures, suites or scripted runners without an explicit test-development request. Use existing checks, short direct calls and actual UI work, with scoped visual capture where needed. A pass count, screenshot, tool self-report or menu does not establish the whole result. Current model, workflow, native platform, motion, sound and external-service observations belong separately in the capability record.
