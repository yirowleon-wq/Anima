# Continuing Anima's development

Anima is a personal project for serious work, making things, going outside, play and quiet time. A character's personality participates in noticing, understanding and choosing what to do; useful help and continuity make the experience worth returning to.

The [capability record](../CURRENT_STATUS.md) describes what exists and what has actually been observed. The [roadmap](../DEVELOPMENT_ROADMAP.md) describes future work; its twelve formal stages are not complete merely because plans and materials exist. Fictional places and selected sample or manual material can support the main experience; real accounts and APIs remain optional extensions.

## Start from the actual project

1. Open [README](../../README.md), [project navigation](../../PROJECT_NAVIGATION.md), the capability record and [continuation](../continuation.md). Install and run from Anima's own directory using its package and lockfiles. Configure private credentials and data separately.
2. Read the [product contract](../PRODUCT_CONTRACT.md), [architecture](../ARCHITECTURE.md) and [visual direction](../../FRONTEND_DESIGN.md). For the chosen task, use the relevant [development skills](../../.agents/skills/project-navigation/SKILL.md), character passport, suitable design and [asset manifest](../../visual-assets/manifest.json).
3. Use the [roadmap](../DEVELOPMENT_ROADMAP.md) and [experience requirements](../EXPERIENCE_REQUIREMENTS.md) to preserve the complete project. Begin with the [Stage 00 Swift foundation](SWIFT_FOUNDATION_AND_CHARACTER_CONTINUITY.md). The [work sequence](WORK_SEQUENCE.md) then organizes the same 38 substantial blocks with their readings, artwork, dependencies and recovery points. The proposed first existing block is [Sakiko's study-and-return sequence](../stages/01-shared-attention.md); the [stage index](../stages/README.md) keeps the full later scope.
4. After real work, record the actual version, usable result, original object and revision, observations, remaining conditions and next start in the continuation. Preserve the same work rather than creating a similar object.

## What must stay together

One assistant loop understands and uses the actual original objects. Notes, materials, learning attempts, calendar records, creations, preparations, memory and actions keep their own owners. References carry stable identity, revision and exact source location. The same composer, admitted message, current draft and return point survive a change of view. Choosing the full cover remains separate from Resume or Back.

Programs remain checked interactive creations with current input returned to the model and persisted by their host. Trial placement does not save a calendar change. A rendered answer does not establish understanding or acceptance. A local workout does not establish institutional acceptance. The synthetic map does not establish real-campus navigation. A blink does not establish a complete gesture. Read the [technical boundaries](TECHNICAL_BOUNDARIES.md) when implementing a replacement.

The longer-term work redesigns the complete Harness, OpenUI and interaction systems in useful stages. Each replacement needs equivalent capabilities and data, one authoritative write path, versioned migration, cancellation and recovery, and an exit condition for temporary adapters. Preserve working behavior. A stage can span healthy sessions.

Formal stage development requires eight substantive workers with exclusive write boundaries and lead acceptance of the integrated result. Each shared contract has one writer. Inspect available tool organization before starting; eight role descriptions do not constitute eight implemented contributions.
