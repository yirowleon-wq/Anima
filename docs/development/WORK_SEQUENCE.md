# Development work sequence

This sequence organizes the **38 substantial blocks defined in the [development roadmap](../DEVELOPMENT_ROADMAP.md)**, including their readings, dependencies, outcomes and recovery points. A [Stage 00 Swift foundation](SWIFT_FOUNDATION_AND_CHARACTER_CONTINUITY.md) precedes them without replacing or renumbering those blocks. Its character, memory and native-continuity obligations apply to each block. This is planned work, not a completion record. [CURRENT_STATUS](../CURRENT_STATUS.md) owns observed capability; [continuation](../continuation.md) owns the current working position.

The current project, working materials and retained artwork are starting points for these blocks. Consult current evidence and actual conditions before beginning; the existence of a work order does not establish a completed stage.

Critical execution requirements are written directly into the twelve stage plans and all 38 work-block bodies: frontend/backend prerequisites, GPT Image design before final affected live interfaces or qualified matching reuse, shared grid and complete Sakiko chain before cast/matrix expansion, actual acceptance, and exact pause/resume. The full readings still supply depth and reasons; opening them is not necessary to discover these basic responsibilities.

The [200 memory/context gates](../scenarios/MEMORY_GATES.md) are integrated through the [38-block acceptance map](../scenarios/MEMORY_GATE_SEQUENCE.md). Each block contains its specific required distinctions, not only IDs or links. They progress from object/subject and current correction to original reading, adoption, lifecycle, presentation, domain work, independent hosts and continuous life. A gate is not a pre-recorded pass, an automatic conversation queue or personal history.

Its work-order entry gives the material order, images, desired experience, usable finish and recovery; read the matching stage plan, Stage 00 continuity obligation and roadmap exit together.
5. Use the current files to assign exclusive implementation boundaries. Each formal stage retains its lead and **eight substantive workers**, including its roadmap responsibilities; a block is a continuation within that stage, not a requirement to discard healthy workers and open eight new sessions. The lead understands the full work, integrates it and personally accepts the real outcome. Verify the available organization before claiming that arrangement is active.

The main experience track uses an intentionally fictional campus with actual authored topology and user-chosen fictional/sample materials. These are valid complete inputs: local operations, Luna responses, visual quality, source identity, state, actions and recovery must genuinely work. Real-campus maps, virtual student-profile construction, private accounts and API connections are not prerequisites. Optional real integrations retain their full design/authority contracts for a separate choice; synthetic results never become official records or physical observations. A promised independent native host or full motion still needs its actual evidence.

These are relative dependencies, not promised dates or a fixed completion window. A meaningful block may span healthy sessions.

**Harness:** 00 hardens the existing loop, memory and character participation while the Mac foundation is migrated; 01 establishes the new turn/semantic/persona entry; 02 establishes capability/provider boundaries; 03 replaces context and cooperative memory; 04 replaces recoverable shared output; 05 replaces ongoing work, preparation, action dispatch and host lifecycle. Do not leave two assistant brains or let both paths dispatch an action. A first character chain is useful progress, not this whole exit.

**Interaction and OpenUI:** 04 establishes relations, versioned works and local adoption; 05 makes transactions and trials real; 06 supplies the complete controllable visual language; 07–08 deepen maps, paper and cross-surface relationships; 09 redesigns and replaces authoring, finite validation, execution, layout feedback, takeover, local state, incremental change and restoration together. Preserve existing good primitives and work compatibility where sound. 10 is demanding sensory/life use and 11 is independent hosting, not substitutes for the 09 system.

For every replacement, first make a capability/data correspondence and select a usable migration slice. Specify the authoritative writer, supported old versions, transaction boundary, privacy/withdrawal fences, cancellation, rollback and adapter retirement. Rollback cannot restore forgotten content, expired approval or a second side effect. The architecture remains an implementation decision informed by the actual code and evidence.

## Stop and resume without creating another management system

Use the existing concise [continuation](../continuation.md). After a meaningful work period, record the actual version and block; where to open the usable result; original object IDs/revisions and draft; real observations; decisions; pending/unknown attempts; one remaining condition; one next action. Mark a proposal, implementation, direct observation and acceptance accurately. Do not maintain a second status grid or copy full product data into the continuation.

If energy, a meaningful allowance limit, a different interest or an external dependency calls for stopping, save the same work and its exact resume condition. For example, a missing signed iOS build condition parks the dependent native step; it does not invalidate completed desktop work or make phone independence pass. A changed source or withdrawn permission requires resolving that object before proceeding, not replaying a prepared prompt with old authority.

At a later authorized opportunity, read the newest continuation and actual files, verify the current source/object and applicable permission, then resume the same eligible unit or choose another legitimate interest. Preserve healthy sessions through waiting, tool failures and normal compaction. Follow the existing strict runtime-failure rules when an actual terminal model failure is established; silence or an ordinary tool timeout is insufficient.
