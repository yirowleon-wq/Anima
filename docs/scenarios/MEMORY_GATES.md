# Two hundred memory and context acceptance gates

These are human-readable engineering acceptance requirements, developed item by item from the complete [two hundred English questions](QUESTIONS.md). They are design material, not executable tests, fixtures, a new runner, a production classifier or anyone's personal biography. The question IDs preserve correspondence; they must never route real conversation by keywords.

All 200 questions retain their full wording below. Each has a first responsible block, needed source context and a specific observable distinction. Its first block accepts only the mechanism and experience actually implemented there. The [38-block map](MEMORY_GATE_SEQUENCE.md) names later expansion/rechecks; required native, audio, full motion and independent-host evidence cannot be borrowed from an earlier text-only observation.

## How to use a gate

Read the requirement as the engineering operator. Give the acting product model only the actual present natural input and sources permitted through their ordinary owners, not this expected outcome or future story steps. Let real responses determine continuation. Do not run a prewritten two-hundred-message queue, preload personal facts or manufacture outcomes to fit the script.

Use selected fictional/sample/manual sources as complete product inputs and label their world accurately. Separate original words, speaker/subject, observation, interpretation, proposal, adoption, attempt and receipt. Provider acceptance or physical-device behavior needs its real independently selected condition. Optional unselected real accounts/providers are not failed main-track gates; a local result never becomes official recognition by renaming it.

Keep location services and location permissions off. The location-withdrawal question is addressed through lawful source/in-flight invalidation with manual or stored synthetic data, not by enabling a sensor for observation. No question grants account access, purchase, communication, new collection, test development or external-action authority.

These rows state acceptance requirements, not a report that they passed. Record actual version, allowed source, relevant operations, owner/result, model/experience scope and remaining condition in the existing current capability/continuation records when observed. A document match, model self-rating, pass count or static image cannot close an unobserved workflow. Use normal product entries and relevant existing checks; create no test code, fixtures, assertion suites or runners from this document.
