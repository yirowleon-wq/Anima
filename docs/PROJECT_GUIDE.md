# Experiences and implementation

Anima is a place to spend time with a companion: understand something difficult, make a small instrument, read together, rearrange a day, explore an imagined place or enjoy an afternoon without a goal. The relationship, useful help and pleasure of using the project matter together.

Experiences retain clear names and authoritative owners. Their inputs may be chosen examples, an authored fictional world, manual records or available real sources. The source and its permissions determine what can be concluded; an imagined event is not a fact about a person. The machine-readable [component map](../runtime/component-map.json) points to existing implementation, examples, support packages and future work. It is navigation, not a second runtime or fact database.

## Things to do

| What I want to do | Capability | Useful input |
| --- | --- | --- |
| Talk, ask something serious, or lightly call the companion | Conversation with Luna | The local Luna connection; the current draft and actual question stay together. |
| Read and keep an idea | Read together; Keep a thought | A chosen file, a passage, or personal writing. Page, selection and return address remain real. |
| Change a day without losing the old arrangement | Arrange the day | Explicit local events and a declared time zone. An example day can exercise the same live controls. |
| Turn an idea into something I can touch | Make and explore together | A wave, equation, diagram, instrument or playful question; the actual inputs persist and return to the conversation. |
| Explore a place | Explore a place together | The authored fictional map and its actual paths. Routing, camera movement, selection and recovery must work within that world. |
| Use course, event or activity information | Learning and course material; activities and places to go | Chosen examples or explicit local imports. The [three existing examples](../examples/) supply the current formats. |
| Feel continuity with a particular character | A recognizable companion; remember what helps | The complete passport, retained original art and permitted shared history. Appearance does not rewrite identity or invent a person's past. |

Start with a scene and a useful piece of content, then follow it through conversation, the working object and return. Fictional places and sample records are legitimate creative inputs; their controls, calculations, source addresses and saved state still need to work. A local record remains a local record. An outside service's acceptance requires that service's actual result.

For position-dependent map, route and workout development, use app-internal simulated fixes and tracks, manual origins or permitted imports. Record source and quality, and never treat simulation as physical arrival or official credit. Do not acquire real device location or enable OS location services or request or grant location permissions on any platform, browser, emulator or guest. This constraint preserves the full independent-device and recovery goals without making native GPS acquisition a current development goal.
