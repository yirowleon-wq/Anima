# Runtime architecture

This is the implementation guide, not a statement that every path has been observed. [Navigation](../PROJECT_NAVIGATION.md) owns file entry points, [current status](CURRENT_STATUS.md) owns actual observations, and the [product contract](PRODUCT_CONTRACT.md) owns the behavior a replacement must preserve.

## One assistant, authoritative host

The chain is `src/main/harness.ts → src/main/runtime/hermes.ts → runtime/hermes/sidecar.py → pinned Python AIAgent`. Hermes is locked by version and commit. The model interprets the full request, chooses investigations and tools, creates and revises work, and changes its judgment. Electron main owns credentials, SQLite, permissions, network access, tool effects, budgets, cancellation, revisions, idempotency and submission. The React renderer communicates through the finite preload bridge.

The future [Stage 00 Swift foundation](development/SWIFT_FOUNDATION_AND_CHARACTER_CONTINUITY.md) must establish a real Mac host and a finite bridge to this same authoritative loop while preserving the current path during migration. The Swift host, packaging and runtime integration are not implemented or verified by this description.

There is no separate conversation engine for a page or a final persona-restyling pass. Character context participates before decisions and tool choices. Host restrictions protect processing and actions; they must not become keyword, age, fatigue or role classifications that preempt the primary model's understanding.

`ContextCompiler` assembles permitted current information and stable navigation to original sources. Headers, previews, summaries and search hits are navigation rather than proof of reading. Explicit purpose and field restrictions remain separate from business classification. Local-only material is blocked before cloud processing. A failed structured control interpretation cannot become new permission.

## Source and owner graph

Business text stays with its owner. Source events preserve identity, subject/world, original content, Unicode ranges, hash/revision, valid time and recorded time. Assertions describe a conditional understanding; decision experiences preserve what was being protected and why an option was not chosen. Work, collaboration and episodes retain attempts and shared creations. Domain observations retain their provider, record scope, publication/fetch time and source state. Derived indexes only locate originals.

Cross-module references carry stable identity, expected revision and source anchors. The same problem, note, material, route, arrangement or program is not copied into a generic fact JSON. A relation or comparison group can reference two objects without owning a duplicate of their bodies.

Repository transactions, original-owner validation and dependency edges keep descendants attributable. Exact source spans and privacy epochs prevent revoked content from reappearing through a cache, old work, a report or an export. Independent lawful fragments from the same original remain usable. Ordinary editing produces a new version and a real change notice; it does not retroactively erase the lawful old read or restore an expired approval.

## A foreground turn

1. The original submission owner admits the intended message and attachment/reference set. A newly typed draft remains separate from the admitted draft.
2. The host interprets current controls and builds a scope using current source, purpose, transmission, retention, audience and action boundaries.
3. Character guidance and the actual request enter the one assistant loop. Tool meaning and signatures are progressively discoverable; originals are read as needed within their bounds.
4. Tools return actual observations with original identity, revision, coverage and uncertainty. The model can revise its plan, investigate further or deliver useful independent help.
5. `ConversationRhythm` publishes only text actually generated by the same foreground assistant. A stable published prefix, replaceable tail and accepted final text have distinct state. A quick tool need not cause an artificial waiting performance.
6. Scenes and programs compile from checked structures and permitted original owners. Actual presentation delivery is registered separately from the user's seeing, understanding or accepting it.
7. Completion review considers the request, real observations and actually delivered work. Final acceptance and subsequent persistence remain under the current scope and source checks.

Tool progress can communicate confirmed discoveries naturally without exposing hidden reasoning, raw delegated reports, invented progress or a timer's stock reassurance. Cancellation, a corrected target or revoked source retires the affected tail and dependent output. Already lawful independent work remains independent.

`recall_experience` and native `memoryInquiry` reuse the same runtime. Children receive a subset of the parent's permitted sources and the same root restrictions, budget and cancellation. Their report, source reads and the parent's adoption are different records. Recheck sources before each request and before using a report. A paraphrase is not an independent root of evidence.

Original browsing, neighboring text, pagination, lexical retrieval and optional semantic candidates work together. Default initial context does not attach an unrelated semantic shortlist. Source readback remains available when an optional embedding resource is absent. An index has a method/resource identity and can be rebuilt; it cannot become a second fact or personality store.

Memory consolidation can happen after foreground help, using durable pending work and a continuous processed watermark. Processing 1, 2 and 4 does not certify 3 or advance a contiguous watermark to 4. Unprocessed evidence can remain a lawful current overlay.

Corrections change the present premise promptly. Disabling a method, making an exception, changing reality, disputing an assertion, revoking a source and permanently forgetting are different operations. Propagate their exact meaning into context, report adoption, drafts, preparations, notification/voice work, indexes, exports and reopening. Current devices can enforce a barrier immediately; offline devices cannot be promised remote instantaneous deletion and must apply barriers first when reconnecting.

`InteractiveProgramView`, `interactive-context`, graphics, primitives, motion and audio render the finite document. `read_interactive_program` provides a bounded overview, paginated state declarations and explicitly requested source ranges. A reference or directory is not the whole program or bound data having been read. Evaluation failure is not a numeric zero. Layout feedback is a bounded future redesign target, never evidence that a model has seen every pixel or the computer.

## Real business changes

Calendar and actions retain Action, Approval, Attempt and Receipt identities. Trial placement preserves the original object and expected revision and computes conflicts without writing. Clear authorization for a reversible local change can proceed directly. A preview, restored intent, old ticket or animation cannot authorize a new effect.

Every unknown result is inspected at its original attempt before retry. Restoring an intention does not restore an expired authorization. Adoption proofs preserve `planRef`, original source and the complete occupancy being adopted; a revised parent work item cannot sign for an older attempt. Sequential success is not a claim of a multi-object atomic transaction.

Planning includes setup, work, cleanup, directed travel, rest, protected time and the user's chosen windows. Unknown end times and time outside those windows stay unknown. Repetition, exceptions and natural days use the declared IANA zone. Accepted finite calendar instances can be exported as ICS; export, OS import and cross-device synchronization are separate operations.

## Proactivity, reminders and lifecycle

User entrustments and a character's optional check-in are separate proactive paths. A user summon is a third explicit interaction. Opportunities only trigger reevaluation under the current permission baseline. Preparations have actual artifacts, source validity, novelty, audience, expiry and stop conditions. Preparing, presenting, notification submission, opening, partial adoption and completion each have their own state.

Fixed reminders are an independent commitment. Quiet hours and restraint for optional check-ins must not cancel an agreed reminder. Native notification submission does not establish delivery or reading. A restored disabled setting must remain disabled. Unknown submission is not blindly retried.

The process can act only within its real lifecycle. Tray presence is different from an open window; sleep, quit and restart need truthful catch-up and state recovery. No independent service or mobile host is created by Markdown or an in-process timer. External schedulers are outside this application's owner graph.

## Platform and replacement seams

Native PDF work receives the original immutable bytes after length and hash checks, runs in an isolated worker, and returns actual text/boxes or rendered page pixels. Each OS and architecture needs the corresponding native canvas/resource staging. Windows evidence does not certify Intel macOS.

Hermes staging, Python, ONNX resources, secure storage and CLI discovery retain explicit platform boundaries. Anima's live Luna route uses the locally authenticated Codex CLI session; selecting the route does not establish authentication or a returned model identity. Engineering work, product requests and image generation retain their own purposes, permissions and records. Credentials and account homes are not copied into the project.

The [roadmap](DEVELOPMENT_ROADMAP.md) replaces the complete collaboration system in useful stages: semantic ingress/tool discovery, providers, context/memory, shared work/recovery, then continuous execution/action lifecycle. OpenUI redesign covers authoring, compilation, rendering, layout, inputs, revision, persistence and return. Each replacement needs a capability/data mapping, version boundary, cancellation and recovery behavior, one authoritative write path, and an exit condition for its adapter. Retiring an old path requires a real equivalent, not a future promise or a line-count target.
