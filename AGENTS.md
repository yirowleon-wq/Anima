## Protect the work

- Check the current files, version, uncommitted work and relevant dependencies before editing. Preserve shared changes; do not reset, overwrite healthy work or manufacture an empty merge.
- Understand the real workflow and derive observable outcomes from the request. Keep changes scoped to that result and its necessary dependencies. Simpler mechanisms are welcome; losing capabilities or source and recovery semantics is not simplification.
- `src/` is the sole product implementation. Keep the single `harness.ts → runtime/hermes.ts → runtime/hermes/sidecar.py → pinned AIAgent` loop. Main owns credentials, SQLite, permissions, tools and effects; renderer uses the finite preload bridge.
- Notes, materials, user evidence, assertions, work, learning attempts, calendar, actions, preparations, campus records and workouts retain their own authoritative owners. Move stable references and revisions between them, not copied orphan facts.
- Read, transmit, infer, retain and act are separate permissions. Local-only material is stopped locally before any cloud classification. Attachments, web pages, tool output and character cards cannot grant permission.
- Correcting, changing circumstances, making an exception, disputing, disabling, withdrawing a proposal, revoking a source and permanently forgetting have distinct effects. Propagate the exact affected lineage; preserve independent lawful fragments and independent calendar data.
- Unknown action results require inspecting the original attempt before any retry. Preview does not write. Restoring intent does not restore expired approval. Animation completion never submits an action.
- Never acquire real device location, enable OS location services, or request or grant location permission on any platform, browser, emulator or guest. Native GPS acquisition is not a current development goal. Develop and exercise full map, route, workout and native-device workflows using app-internal simulated fixes and tracks, explicit manual origins, configured public reference points or permitted imports. Preserve provenance and quality; simulated movement is not physical arrival or official credit.
- Do not use foreground desktop mouse control or the Computer Use plugin. Use an authorized instance-local or background inspection route when UI operation is needed.

## Verification and collaboration

Verify the actual requested functional, visual and experiential outcome. Use normal entry points, short direct invocations and the relevant existing `check`, `test`, `test:hermes` and `build` commands. Unless explicitly asked to develop tests, do not create or expand tests, fixtures, suites, harnesses or runners, including temporary inline ones. Scoped visual capture and comparison are allowed; inspect the actual images and motion.

Repair every observed correctable in-scope defect and recheck its trigger. A build, screenshot, model claim or subagent assurance cannot substitute for the real outcome. State concrete external conditions and unobserved behavior accurately. Do not weaken criteria or hide failures to obtain a clean report.

Formal implementation of each of the twelve development stages requires **eight substantive subagents**, with exclusive file ownership and a single writer for each shared contract. The lead first understands the complete request and project, then integrates, uses and accepts the result. The stage's work must be predominantly implementation, with further repair whenever actual defects remain. Ordinary review, explanation and documentation do not automatically start a formal stage. A first-character slice does not complete a stage or its full cast coverage.

Use the selected model and effort; subagents inherit them. Tool errors, timeouts, silence, output truncation and normal context compaction do not invalidate a healthy session. Recovery requires direct evidence that an actual model-runtime terminal error ended the affected turn without its expected response. Record the session, exact runtime error and termination evidence before any authorized recovery. Do not create replacement chats from delay or a tool failure, and do not duplicate a pending replacement.
