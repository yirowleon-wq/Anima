# Anima visual assets

The visual collection includes artwork already used by the application and qualified originals kept for design work. The working library contains 948 currently available unchanged original-size files, including 48 explicitly identified technical production components. An unused good image remains useful material; a newer draft does not replace the kept collection.

| Entry | Contents and use |
| --- | --- |
| [Runtime assets](runtime) and [positive manifest](manifest.json) | Exact files referenced by the current application, including whole scenes, matched layers, portraits, companion bodies/tails, ambient plates and textures. Follow actual imports and the matching registration before changing a resource. |
| [Kept original library](library/README.md) | Original-size unused room, character, companion, surface and atmosphere studies, with an English file index, hashes, concrete use and future work links. Static preservation does not adopt an image into the application. |
| [Design references](design) | Qualified paper and atmospheric references. Whole-page designs describe a composition; live text, mathematics, controls and source objects remain real components. |
| [Coverage inventory](coverage.json) and [coverage method](../docs/design/CHARACTER_COVERAGE.md) | Actual character/page/theme slots, material references and the distinction between missing, static fallback, compatible reuse, art approval and runtime evidence. Required motion remains a future requirement when its material is missing. |
| [Calibration records](calibration) | Exact canvas geometry and permitted matching support/contact data. Similar-looking rooms are not interchangeable cameras or seats. |
| [Incoming art](incoming/README.md) | The intake location and preservation procedure for a further collection when it is actually supplied. |
| [Optional design studies](optional-drafts/requests.json) | Three separately recorded design candidates, with output identities, adapted briefs and recorded request hashes. They are not replacements for kept art or completed stages. |

Read the [visual working materials](../docs/materials/visual/README.md), [visual direction](../FRONTEND_DESIGN.md), [presence system](../docs/design/PRESENCE_SYSTEM.md) and [motion pipeline](../docs/design/CHARACTER_MOTION_PIPELINE.md) with the relevant full [character passport](../docs/characters/README.md). Then use the [roadmap](../docs/DEVELOPMENT_ROADMAP.md) and [stage plans](../docs/stages/README.md) to choose substantial work.

The visual work ahead includes a first-character sequence, expansion to the other characters, coherent performances and the interface redesign. A slot marked missing or static fallback is an inventory state; required normal motion remains open.

Preserve original dimensions and image detail. Keep the whole mother composition with its exact layers, props, light, support and camera. Review an isolated figure against its own room before adopting it; a glow is not furniture and a plausible static body does not prove arbitrary movement between seats. Severe structural failures are not generation inputs.

Vertical docking reuses the eligible horizontal companion through a ninety-degree transform of that same artwork. Keep its complete body and tail together, align the transformed support to the actual edge, and allow immediate user takeover. A separately drawn upright cat is not a production option.

Image identity, generation-request provenance, static approval, layer compatibility and actual runtime adoption are separate records. Use the recorded request where it is available and identify adapted design briefs as such; an unknown exact prompt stays unknown. The material library preserves design intent without inventing a tool call or treating painted examples as live data.

Character artwork is unofficial fan art; project-original companion forms and interactions are interpretations. The [artwork index](library/index.json) and [character passports](../docs/characters/README.md) retain the available resource and reference provenance.
